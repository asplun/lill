# 发布与安装包

## 选择下载文件

从 [GitHub 最新发布](https://github.com/asplun/lill/releases/latest) 下载：

| 文件 | 用途 |
|---|---|
| `lill-v1.3.3.zip` | 宝塔、1Panel 文件管理器上传和解压 |
| `lill-v1.3.3.tar.gz` | SSH 或自动化部署 |
| `SHA256SUMS` | 校验以上两个包是否完整 |
| GitHub 自动提供的 `Source code` | 源码快照，前端需要自行安装依赖并构建 |

两种安装包内容相同，解压后都有 `lill/` 目录。前端已直接生成在 `frontend/`，
没有 `frontend/dist/`，无需在服务器安装 Astro 或构建前端。仍须安装后端运行依赖：

```bash
cd lill/backend
npm install --omit=dev
# 或使用锁定依赖：pnpm install --prod --frozen-lockfile
```

然后按照 [部署指南](部署指南.md) 配置静态网站、API 反向代理和 Node 后端。
首次安装推荐 Node.js 24；支持 22.13.0 及以上版本，备份附件需要系统 `zip` 命令。
访问 `/admin/` 填写站点和管理员信息；SQLite 由系统初始化，不需要创建 MySQL 数据库。

## 包内内容与边界

- `backend/`：REST API、SQLite 初始化代码、默认 Hello World 插件、PM2 配置示例和测试。
- `frontend/`：可直接部署的静态前后台、Astro 源码、默认主题与默认主题后端扩展。
- `README.md`、`CHANGELOG.md`、`LICENSE`、`docs/`、`screenshots/`：介绍、变更、开发和部署文档。
- `RELEASE.json`：系统版本、完整源码提交、源码时间、构建 Node 版本及内置主题清单。

包内没有 `node_modules`、数据库、上传文件、JWT 密钥、缓存或第三方主题。
trim3、solbrin 等第三方主题单独安装、升级；更新系统时保留原有主题目录和配置。
系统版本与默认主题版本独立，默认主题的 `theme.json.version` 不必等于系统版本。

## 验证下载完整性

把安装包和校验文件放在同一目录，在 Linux 上执行：

```bash
sha256sum -c SHA256SUMS
```

只下载其中一种格式时，可查看校验文件中对应的一行；macOS 使用 `shasum -a 256 <文件名>` 比较。
校验文件验证下载完整性；发布来源仍应核对仓库 `asplun/lill` 和对应版本标签。

## 升级已有站点

先备份数据库一致性快照、附件、已安装主题和本机进程配置。解压到新目录检查
`RELEASE.json`，再停止后端或进入维护窗口，按目录选择同步程序文件。
保留 `backend/data/`、`backend/uploads/`、`backend/ecosystem.config.cjs` 中的本机设置，
以及原有环境变量。`DB_PATH`、`UPLOAD_DIR`、`THEMES_DIR` 自定义路径以实际进程为准。

核心前端文件和默认主题可更新；不要删除或覆盖其他主题、额外插件。根据后端锁文件更新依赖，
启动原有后端进程，再验证登录、文章链接、主题设置和插件设置。完整步骤见部署指南。v1.3.3 无数据库结构变更，覆盖文件后重启后端即可完成升级。
不要直接把安装包整体覆盖到运行中的站点，也不要用安装包中的配置示例替换生产密钥。

## 维护者生成安装包

在源码仓库准备好提交和标签，安装 Node.js、pnpm 和 Python 3，然后执行：

```bash
python3 scripts/package-release.py --ref v1.3.3 --output /tmp/lill-release-v1.3.3
```

脚本从指定 Git 提交导出源码，在临时目录安装锁定的前端依赖、构建前端，只打进仓库内置的主题
（当前为 `default`，白名单常量在脚本内维护），再生成两种归档和 SHA256SUMS；
包内 `RELEASE.json` 记录构建用的提交与主题列表。已存在同名产物时会停止，避免静默覆盖。
本地未提交改动、被忽略的第三方主题和运行数据不会进入安装包。

发布前应从解压后的包全新安装并验证：安装向导、版本接口、登录、前台默认主题、主题与插件设置、
缺失资源 404；确认 Release 标签指向 `RELEASE.json.commit`，上传后再次下载验证 SHA256。
测试站升级另行保留数据库、附件、密钥和第三方主题，不能用清空目录的方式部署。
