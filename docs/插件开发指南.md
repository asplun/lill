# lill 插件开发指南

> 适用版本：lill v2（Node.js + Astro 静态前端 + SQLite）
> 插件 = **一个文件夹**，放进 `backend/plugins/`，后台「扩展 → 插件管理」启用即可，**无需重启服务**。

---

## 0. 一分钟理解 lill 插件

| | Typecho | WordPress | **lill** |
|---|---|---|---|
| 插件形态 | 文件夹 + `Plugin.php` | 文件夹 + `xxx.php` | 文件夹 + `index.js` |
| 清单文件 | `Plugin.php` 注释头 | `xxx.php` 注释头 | `plugin.json` |
| 入口 | `Plugin::activate()` | `register_activation_hook()` | `export function activate(ctx)` |
| 停用 | `Plugin::deactivate()` | `register_deactivation_hook()` | `export function deactivate(ctx)` |
| 注册接口 | `Helper::addRoute()` | `add_action('rest_api_init')` | `ctx.route()` |
| 挂载钩子 | `Typecho_Plugin::factory()` | `add_action()` / `add_filter()` | `ctx.on()` |
| 后台菜单 | `Helper::addPanel()` | `add_menu_page()` | `ctx.addAdminMenu()` |
| 配置存储 | `Options::plugin()` | `get_option()` | `ctx.getConfig()` / `ctx.setConfig()` |

一句话：**把 PHP 的插件类换成 ESM 模块，把 `add_action` 换成 `ctx.on`**，其余思路完全一致。

## 1. 目录结构

```
backend/plugins/<插件目录名>/
├── plugin.json     # 【必须】插件清单
├── index.js        # 【必须】入口，导出 activate / deactivate
├── lib/            # 可选：拆分的模块
├── assets/         # 可选：图片等静态资源
└── README.md       # 可选：说明
```

规则：

- **插件 ID = 目录名**，只允许字母、数字、`-`、`_`、`.`，且必须以字母或数字开头。
- 目录名以 `.` 开头表示「内部目录」，不会被扫描（`.tmp-*` / `.trash-*` / `.bak-*` 是安装器的工作目录）。
- 只有 `plugin.json` 存在且能解析的目录才会出现在后台列表里。
- 插件模块用 **ESM** 语法（`import` / `export`），Node ≥ 22。

## 2. plugin.json 规范

```jsonc
{
  "name": "我的插件",              // 必须，后台显示名
  "version": "1.0.0",             // 必须，语义化版本
  "description": "一句话简介",      // 可选
  "author": "作者名",              // 可选
  "homepage": "https://...",      // 可选
  "settings": [                   // 可选：后台「插件设置」自动生成表单
    {
      "group": "常规",            // 分组名，同组自动归类
      "key": "enabled",           // 变量名，插件里用 ctx.getConfig('enabled') 读取
      "label": "启用功能",
      "type": "checkbox",         // checkbox | text | textarea | select | number | color
      "default": true
    }
  ]
}
```

> `dir`、`active`、`hasSettings` 由系统在接口返回时补上，**不要写进 `plugin.json`**。

### settings 字段类型

| `type` | 渲染控件 | 存储类型 |
|---|---|---|
| `text` | 单行输入框 | string |
| `textarea` | 多行文本域 | string |
| `select` | 下拉框（需配 `options: [{value,label}]`） | string |
| `checkbox` | 复选框 | boolean |
| `number` | 数字输入框 | number |
| `color` | 取色器 | string（`#rrggbb`） |

保存时系统会**按 `type` 归一化**再写入，插件用 `ctx.getConfig(key, default)` 读到的就是上表的类型。
字段与 `theme.json` 的 `settings` **完全同构**，主题设置那套写法可以直接搬过来。

## 3. 入口 index.js

```js
export async function activate(ctx) {
  // 插件被启用时调用：注册路由、挂 hook、加后台菜单、读配置……
}

export async function deactivate(ctx) {
  // 插件被禁用时调用：可做清理。
  // 路由 / hook / 后台菜单由系统自动摘除，这里一般只做业务清理。
}
```

生命周期：

```
上传 ZIP ──▶ 写入 plugins 表（active=0，未启用）
启用     ──▶ 加载 index.js ──▶ activate(ctx)
禁用     ──▶ deactivate(ctx) ──▶ 摘除路由/hook/菜单 ──▶ 卸载模块
卸载     ──▶ 停用 ──▶ 目录移入 .trash-* 回收 ──▶ 删除数据库记录
```

**热加载**：启用/禁用立即生效，不用重启 Node 服务。

## 4. ctx 能力速查

| 方法 | 说明 |
|---|---|
| `ctx.route(method, path, handler, auth?)` | 注册 REST 路由。`auth=true` 时需登录（自动校验 JWT） |
| `ctx.on(hookName, handler)` | 监听系统钩子 |
| `ctx.off(hookName, handler)` | 取消监听（一般不需要，禁用时自动摘除） |
| `ctx.addAdminMenu({id, title, icon, order, url?})` | 注册后台菜单项 |
| `ctx.getConfig(key, default)` | 读取插件配置（存 `options` 表，key 前缀 `plugin_<dir>_`） |
| `ctx.setConfig(key, value)` | 写入插件配置（值会 JSON 序列化，支持对象/数组） |
| `ctx.db` | SQLite 句柄（`prepare(...).get()/all()/run()`）。**建议只读，写自己的表请加插件前缀** |
| `ctx.settings` | 站点设置读取器 |
| `ctx.json(res, data, status?)` / `ctx.error(res, msg, status?)` | 统一响应封装 |
| `ctx.uid()` | 生成唯一 ID |
| `ctx.dir` / `ctx.dirName` | 当前插件目录的绝对路径 / 目录名 |
| `ctx.log(...)` | 带 `[plugin:<dir>]` 前缀的日志 |

### 4.1 注册路由

```js
ctx.route('GET', '/api/v1/hello', (req, res) => {
  ctx.json(res, { message: 'Hello!' });
});

// 需要登录的路由（第 4 个参数传 true）
ctx.route('POST', '/api/v1/my-plugin/do', async (req, res) => {
  ctx.json(res, { ok: true });
}, true);
```

- 路径必须以 `/api/v1/` 开头；避免与 core 路由重名。
- 插件路由在 core 路由之后注册，`/api/v1/admin/xxx` 这类前缀建议带上自己的插件名。
- 禁用插件时，它注册的路由会被**自动摘除**，再次访问返回 404。

### 4.2 插件设置（后台自动生成表单）

只要 `plugin.json` 里写了 `settings`，后台「扩展 → 插件管理」的插件行就会出现**「设置」按钮**，
点进去是按 `group` 分组渲染的表单，保存后写入 `options` 表（key 前缀 `plugin_<目录名>_`）。

对应的后台接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/plugins/:dir/config` | 返回 `{ schema, values }` |
| PUT | `/api/v1/admin/plugins/:dir/config` | 保存设置（**只接受 schema 中声明过的 key**） |

插件侧只需要读：

```js
const text = ctx.getConfig('text', '默认文案');
```

> 值统一按类型归一化后 JSON 序列化存储，与 `ctx.setConfig()` 写入的数据**同一份**，
> 后台表单和插件代码读写的是同一个 key，不会出现两份配置。

### 4.3 注册后台菜单

```js
ctx.addAdminMenu({
  id: 'my-plugin',                    // 唯一标识
  title: '我的插件',                   // 侧边栏显示名
  icon: '🧩',                         // 图标（emoji 或文本）
  order: 100,                         // 排序，越小越靠前
  page: 'plugin-settings:my-plugin',  // 可选：菜单点开后进入哪个后台页面
  url: '/my-plugin/panel'             // 可选：直接跳转到插件自带的页面（优先级高于 page）
});
```

三种落点，按需选一种：

| 写法 | 点击菜单后 |
|---|---|
| `page: 'plugin-settings:<目录名>'` | 打开**自动生成的插件设置页**（推荐，有 `settings` 时用这个） |
| `url: '...'` | 直接 `location.href` 跳转到插件自带的页面 |
| 都不写 | 打开一个提示面板，并自动引导到设置页（若插件有 `settings`） |

菜单会出现在后台侧边栏「扩展」分组下。

## 5. 系统钩子（Hook）清单

钩子为**同步广播**：按注册顺序依次调用，单个插件抛错不影响其他插件和 core。

| 钩子名 | 触发时机 | 回调参数 |
|---|---|---|
| `post.saved` | 文章/页面新建或更新后 | `(post, { isNew })` |
| `post.deleted` | 文章删除后 | `(post)` |
| `comment.saved` | 前台提交评论成功后 | `(comment, { isNew: true })` |
| `comment.status` | 后台修改评论状态 | `({ id, status })` |
| `comment.deleted` | 后台删除评论 | `(comment)` |
| `user.created` | 后台新建用户 | `(user)` |
| `user.login` | 用户登录成功 | `({ id, username, role, ip })` |
| `media.uploaded` | 后台媒体上传成功 | `(media, { isNew: true })` |
| `media.deleted` | 后台删除媒体 | `(media)` |
| `theme.activated` | 后台切换主题 | `({ themeId })` |
| `options.saved` | 后台保存站点设置 | `(items)` |
| `plugin.config.saved` | 后台保存某个插件的设置 | `({ dir, values })` |

示例：

```js
ctx.on('post.saved', (post, meta) => {
  ctx.log(meta.isNew ? '新文章' : '更新文章', post.title);
});

ctx.on('comment.saved', (comment) => {
  // 比如：把新评论推送到第三方通知服务
});
```

## 6. 完整示例：访问计数器

```
backend/plugins/visit-counter/
├── plugin.json
└── index.js
```

`plugin.json`

```json
{
  "name": "访问计数器",
  "version": "1.0.0",
  "description": "统计文章阅读次数并提供查询接口",
  "author": "your-name"
}
```

`index.js`

```js
export async function activate(ctx) {
  // 1. 公开接口：读取某篇文章的计数
  ctx.route('GET', '/api/v1/visit-counter/:cid', (req, res, params) => {
    const n = ctx.getConfig('count_' + params.cid, 0);
    ctx.json(res, { cid: params.cid, count: n });
  });

  // 2. 监听评论保存，记录活跃度
  ctx.on('comment.saved', (comment) => {
    const total = ctx.getConfig('comment_total', 0) + 1;
    ctx.setConfig('comment_total', total);
    ctx.log('累计评论数：', total);
  });

  // 3. 后台菜单
  ctx.addAdminMenu({ id: 'visit-counter', title: '访问计数', icon: '📈', order: 90 });

  ctx.log('访问计数器已启用');
}

export async function deactivate(ctx) {
  ctx.log('访问计数器已停用');
}
```

## 7. 默认插件：Hello World 公告栏

`backend/plugins/hello-world/` 是随系统附带的示例插件，**它本身就是一个能用的功能**，不是空壳：

- **后台可配置**：`plugin.json` 声明了 7 个设置项（公告文字、显示位置、背景色、文字颜色、显示上限、事件开关），
  后台「扩展 → 插件管理 → 设置」直接改。
- **侧边栏菜单**：注册了「📣 公告栏」，点开就是它的设置页。
- **前台可调用**：`GET /api/v1/hello` 返回当前公告配置，主题拿到即可渲染。

主题里这样用：

```js
const { data } = await (await fetch('/api/v1/hello')).json();
if (data.enabled) {
  // data = { text, position, bg_color, text_color }
  renderBanner(data);
}
```

- **事件统计**：监听 `post.saved` / `comment.saved` / `theme.activated` 计数，
  `GET /api/v1/hello/stats`（需登录）可查看。

它同时是阅读插件源码的最佳入口——把 `index.js` 读一遍，插件机制的四种能力就都清楚了。

## 8. 打包与安装

### 7.1 ZIP 打包

支持两种结构，任选其一：

```
# 方式 A：ZIP 根目录直接是插件内容
my-plugin.zip
├── plugin.json
└── index.js

# 方式 B：带一层插件目录（推荐）
my-plugin.zip
└── my-plugin/
    ├── plugin.json
    └── index.js
```

命令：

```bash
cd backend/plugins
zip -r my-plugin.zip my-plugin -x "*.DS_Store" -x "__MACOSX/*"
```

### 7.2 后台安装

后台「扩展 → 插件管理」→ 上传 ZIP → 列表中出现 → 点「启用」。

### 7.3 手动安装

直接把插件文件夹拷进 `backend/plugins/`，在后台插件列表启用即可（刷新页面后可见）。

## 9. 安全约定

- **不要**在插件里硬编码密钥；用 `ctx.setConfig()` 存到 `options` 表。
- 插件路由默认公开；涉及写操作/敏感数据务必传 `auth = true`。
- 插件目录名与 ZIP 内的路径会被校验，禁止 `..` 与绝对路径。
- 插件以**主进程内模块**方式运行，拥有完整 Node 权限——只安装可信来源的插件。
- 插件写数据库时，表和字段建议加 `plugin_<dir>_` 前缀，避免与 core 表冲突。

---

## 10. 调试

- 插件日志：`ctx.log()`，输出形如 `[plugin:my-plugin] xxx`。
- 查看 Node 日志：

```bash
pm2 logs lill-backend --lines 100
```

- 插件激活失败时，服务会打印 `✗ 插件激活失败：<dir> — <原因>`，且不影响其他插件。
