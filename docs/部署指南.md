# lill v1.4.0 部署指南

部署结构：Nginx / OpenResty 提供 `frontend/` 静态文件，将 `/api/` 转发给 Node 后端。后端使用原生 `node:http` 和内置 `node:sqlite`，无需外部数据库服务。

[发布说明](发布说明.md) · [更新日志](../CHANGELOG.md) · [API 文档](API文档.md)

## 1. 环境与目录

| 项目 | 要求 |
|---|---|
| Node.js | 推荐 24 LTS，最低 22.13.0；无需 `--experimental-sqlite` |
| Nginx / OpenResty | 提供静态站点、API 反向代理和 HTTPS |
| 进程管理 | 面板 Node 项目管理或 PM2，单实例运行 |
| 系统工具 | 附件备份需要 `zip`；源码构建同步需要 `rsync` |
| 包管理器 | 后端可用 npm 或 pnpm；本文源码前端构建使用 pnpm |

本文以 `/www/wwwroot/lill` 为示例路径。宝塔、1Panel、裸机及容器的实际目录和运行用户各不相同，请按本机配置替换；面板内安装的 Node 也不一定进入宿主机终端的 `PATH`。

```text
lill/
├── backend/
│   ├── server.js
│   ├── ecosystem.config.cjs
│   ├── data/                  # 默认数据库 lill.db、backups/，运行后产生
│   ├── uploads/               # 默认附件目录，运行后产生
│   └── plugins/
└── frontend/                  # Nginx root
    ├── index.html             # 发布包已包含；源码构建后同步
    ├── admin/
    ├── _astro/
    └── themes/default/        # 保留完整主题，含 backend/ 扩展
```

同机部署可用 `127.0.0.1:3000` 访问后端。**当前源码固定监听 `0.0.0.0`，未读取 `HOST` 环境变量**；请通过防火墙、安全组或容器端口映射限制 3000 端口，仅允许代理访问，对公网开放 80/443。

## 2. 准备程序

以下两种方式任选一种，均在新目录准备，勿直接解压覆盖运行中的站点。

### 2.1 使用发布包

从 [GitHub Releases](https://github.com/asplun/lill/releases) 下载：

- `lill-v1.4.0.zip`
- `lill-v1.4.0.tar.gz`

两种包解压后均为顶层 `lill/`，包含仓库跟踪的源码及预构建静态文件。静态文件直接放在 `frontend/`，包内没有 `frontend/dist/`；仅包含默认主题及其后端扩展、内置插件，不包含数据库、上传文件、`node_modules`、密钥或第三方主题。

```bash
# 示例：压缩包已上传到 /www/wwwroot，且该目录下尚无 lill/
cd /www/wwwroot
tar -xzf lill-v1.4.0.tar.gz
cd lill/backend
npm install --omit=dev
```

ZIP 可通过面板解压。使用 pnpm 时，将后端依赖安装命令改为 `pnpm install --prod --frozen-lockfile`。**发布包不需要安装前端依赖或执行 Astro 构建**。

GitHub 自动生成的 `Source code` 归档没有预构建静态文件，需按源码流程构建。

### 2.2 使用源码

```bash
cd /www/wwwroot
git clone https://github.com/asplun/lill.git
cd lill
git checkout v1.4.0
cd backend
npm install --omit=dev
# 后端也可使用：pnpm install --prod --frozen-lockfile
cd ../frontend
pnpm install --frozen-lockfile
pnpm run build
rsync -a --exclude='/themes/' dist/ ./
```

必须安装两端依赖，再构建并同步静态文件。`frontend/dist/` 是构建暂存目录，Nginx 根目录仍指向 `frontend/`；排除 `themes/`，避免用缺少后端扩展的构建副本覆盖完整主题。可在本地完成构建后上传同步后的文件，无需在生产服务器构建。

维护者生成发布包的命令如下，需安装 Python 3、Node.js 和 pnpm，在源码根目录执行：

```bash
python3 scripts/package-release.py --ref v1.4.0 --output /tmp/lill-release
```

[打包脚本](../scripts/package-release.py)从指定 Git 引用导出干净源码，仅构建默认主题，再将构建输出合并到包内 `frontend/`；不会把 `dist/` 作为发布目录。安装者可直接使用其输出的两个压缩包，并通过 `SHA256SUMS` 校验下载完整性，详见[发布说明](发布说明.md)。

## 3. 启动后端

进程级参数集中写入 `backend/.env`（参考同目录的 `.env.example`），至少可配置 `PORT`（默认 `3000`）、`HOST`（默认 `0.0.0.0`）、`JWT_SECRET`、可选 `FRONTEND_URL`、`DATA_DIR` 和 `UPLOAD_DIR`。`.env` 不提交到仓库。未显式设置 `JWT_SECRET` 时，首次启动会生成并以 `0600` 权限保存到 `DATA_DIR/jwt-secret.txt`，后续重启复用；备份迁移时也应保留该文件。`FRONTEND_URL` 仅作为额外允许的 CORS 来源，不是站点地址。

**站点地址在后台「设置 → 站点 URL」中填写，不在 `.env` 配置。** 留空时公开页面 URL 和 CORS fallback 使用当前请求 Host。端口改动时须同步 Nginx 配置中的 `proxy_pass`，以及本指南中的本地健康检查地址。

进程用户需要读写数据、附件和备份目录；后台安装主题或插件时，也需要对应目录的写权限。不要将整个项目设为所有人可写。

使用 PM2 时配置服务器私有的 `backend/.env`，PM2 配置不再承载进程参数，然后启动：

```bash
cd /www/wwwroot/lill/backend
pm2 start ecosystem.config.cjs
pm2 save
curl --fail http://127.0.0.1:3000/api/v1/install/status
```

若环境没有 PM2，可先用 `npm install -g pm2` 安装，或直接使用面板进程管理。PM2 的开机启动按 `pm2 startup` 输出配置；面板托管时使用面板自带的开机启动机制。

临时调试可在已配置环境变量的终端运行 `node server.js`。Node 后端不提供前台或后台静态页面，完整访问还需下一节的静态站点配置。

## 4. Nginx / OpenResty

创建一个静态站点，根目录设为 `/www/wwwroot/lill/frontend`。以下为 HTTP 示例；按实际域名、目录和上游地址调整，合并到已有站点配置时保留面板生成的证书、验证目录等内容，避免重复的 `location`。完整站点模板见 [deploy/nginx.conf.example](../deploy/nginx.conf.example)。

**用宝塔面板时不要整体替换 vhost**，见 [5.1 宝塔面板](#51-宝塔面板9x--11x-实测路线)：面板托管的证书块、伪静态 `include`、验证目录都在那份配置里，整体替换后这些托管点会全部失效。面板下只需把 [deploy/baota-rewrite.conf](../deploy/baota-rewrite.conf) 贴进「伪静态」。

```nginx
server {
    listen 80;
    server_name blog.example.com;
    root /www/wwwroot/lill/frontend;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 160s;
        client_max_body_size 50M;
    }

    # RSS 必须映射到真实 API，不能将 /feed.xml 原样转发到后端根路径。
    location = /feed.xml {
        proxy_pass http://127.0.0.1:3000/api/v1/feed;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 站点地图与 robots 由后端生成，必须映射到真实 API；否则 /sitemap.xml 会落到首页 HTML。
    location = /sitemap.xml {
        proxy_pass http://127.0.0.1:3000/api/v1/sitemap.xml;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /robots.txt {
        proxy_pass http://127.0.0.1:3000/robots.txt;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 自定义 UPLOAD_DIR 时同步调整；容器中必须挂载到代理可读路径。
    location ^~ /uploads/ {
        alias /www/wwwroot/lill/backend/uploads/;
        expires 30d;
    }

    # 完整主题需留在磁盘，但不对外提供服务端源码与依赖。
    location ~ ^/themes/[^/]+/(backend|node_modules)(/|$) { return 404; }
    location /themes/ {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }
    location ^~ /_astro/ {
        try_files $uri =404;
        add_header Cache-Control "public, max-age=2592000, immutable";
    }
    location = /api.js {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }
    location = /theme.js {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }
    location ~ ^/admin/.+\.(css|js|map|svg|png|ico|woff2?)$ {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }

    # 源码部署与发布包均可能保留这些文件，不作为站点资源提供。
    location ~ ^/(src|public|dist|node_modules)(/|$) { return 404; }
    location ~ ^/(package(-lock)?\.json|pnpm-lock\.yaml|pnpm-workspace\.yaml|astro\.config\.mjs)$ { return 404; }
    location ~ (^|/)\.(?!well-known(/|$)) { return 404; }

    location /admin/ {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /admin/index.html;
    }
    location /post/     { try_files $uri $uri/ /post/index.html; }
    location /category/ { try_files $uri $uri/ /category/index.html; }
    location /tag/      { try_files $uri $uri/ /tag/index.html; }
    location /page/     { try_files $uri $uri/ /page/index.html; }
    location /search/   { try_files $uri $uri/ /search/index.html; }
    location /archive/  { try_files $uri $uri/ /archive/index.html; }

    # 自定义永久链接由通用外壳携带实际 pathname 请求 bootstrap。
    location / {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /index.html;
    }
}
```

保存前通过面板或 `nginx -t` 校验，再重载对应 Nginx / OpenResty 实例。通过面板或证书工具配置 HTTPS；证书路径以实际安装为准，启用后将 HTTP 跳转到 HTTPS。

静态资源缺失应返回 404，不能返回首页 HTML。`/theme.js` 是通用引擎，不要 alias 到某个主题脚本。自定义内容路径通过 `/index.html` 回退，缺失内容由 bootstrap API 返回 404；静态外壳本身可能仍返回 HTTP 200，不属于 SSR 状态保证。

附件也可由后端提供 `/uploads/`，但当前后端仅允许部分图片类型；如需完整附件下载，优先使用上面的 Nginx 文件映射。

## 5. 面板与裸机配置

<!-- baota:start -->
### 5.1 宝塔面板（9.x / 11.x 实测路线）

本节以域名 `blog.example.com`、程序目录 `/www/wwwroot/lill` 为例。整条路线只用面板点点点，**不需要手工改 vhost 配置文件、不需要装 PM2 管理器、不需要在面板里找「纯静态」站点类型**。

三条事实决定了这条路线（宝塔 11.7.0 + nginx 1.31.1 实测）：

- 面板生成的站点 vhost 里本来就有 `include /www/server/panel/vhost/rewrite/<站点名>.conf;`，这一行在 `server {}` **内部**，所以伪静态文件里可以写完整的 `location` 块。
- 面板保存伪静态时会先 `cp` 备份、再跑一遍 `nginx -t`，语法错就自动回滚，**写坏了不会把站弄挂**。
- 面板静态站 vhost 自带 `location ~ .*\.(js|css)?$`（12h 缓存）和 `location ~ .*\.(gif|jpg|...)$`（30d 缓存），这两条是正则，优先级高于普通前缀。所以片段里的前缀规则一律用 `^~`，否则主题改了看不到效果。

#### 5.1.1 装面板与运行环境

1. 按 [宝塔官网](https://www.bt.cn/) 的官方命令装面板，登录后改掉初始账号密码。
2. 「软件商店」→「运行环境」装 **Nginx 1.25 或更新**（[`deploy/nginx.conf.example`](../deploy/nginx.conf.example) 里用了 `http2 on`，1.25.1 才有这条指令；1.24 及以下会报 `unknown directive "http2"`）。
3. 「软件商店」装 **Node.js 版本管理器**，进入后装 **Node 24 LTS**，点该版本旁的「命令行版本」设为默认。
4. 面板「终端」执行 `node -v`，必须是 `v24.*`（最低 `v22.13.0`）。版本不够会报 `Cannot find module 'node:sqlite'`。
5. **不要装「PM2 管理器」**。新版面板已经没有这个插件（`软件商店` 里搜不到，插件目录里只有 `nodejs`/`redis`），进程托管用它自带的「Node 项目」。

#### 5.1.2 上传解压发布包

1. 下载 `lill-v1.4.0.zip`（不要下载 GitHub 自动生成的 `Source code`，那个没有预构建前端）。
2. 「文件」进 `/www/wwwroot/`，上传后右键「解压」到当前目录。
3. **确认项目根正好是 `/www/wwwroot/lill`**：进目录能看到 `backend/`、`frontend/`、`deploy/`。如果变成 `/www/wwwroot/lill/lill` 这种双层，进外层把里层内容全选剪出、删掉外层多余目录。
4. 前端已预构建在 `frontend/`，**不要在服务器跑 Astro 构建**。

#### 5.1.3 装后端依赖

面板「终端」执行：

```bash
cd /www/wwwroot/lill/backend && npm install --omit=dev
```

装完确认 `ls node_modules | head` 有内容。没装成功时，后面建 Node 项目会直接报「请先到模块管理中点击【一键安装项目模块】」。

#### 5.1.4 建站点（HTML 项目）

1. 「网站」→「HTML项目」→「添加HTML项目」（有的版本入口是「添加站点」后选 `HTML` 类型；找不到 HTML 就先建普通站点，效果一样）。
2. 域名填 `blog.example.com`，根目录填 `/www/wwwroot/lill/frontend`。
3. **不要建 Node 项目**：面板的 Node 项目会生成整站反代 `location / { proxy_pass http://127.0.0.1:3000; }`，而 lill 后端只提供 `/api/*`，整站反代会让前台全部 404。后端要用 5.1.6 里「不绑域名」的方式跑。
4. FTP、数据库都不用勾（SQLite 内置，不需要 MySQL）。

建好后到「网站」列表点该域名 →「设置」，确认「网站目录」是 `/www/wwwroot/lill/frontend`。

#### 5.1.5 把 lill 路由贴进「伪静态」

这是整条路线里唯一需要复制粘贴的地方，内容在仓库 [`deploy/baota-rewrite.conf`](../deploy/baota-rewrite.conf)。

1. 「网站」→ 该域名 →「设置」→「伪静态」。
2. 下拉里随便选一个模板（比如 `default`）再清空，或者直接清空文本框——目的是让面板把 vhost 里那行 `include .../rewrite/<站点名>.conf;` 从注释状态激活。
3. 把 `deploy/baota-rewrite.conf` 全文粘进文本框，**只改其中的上传目录这一行**（默认已是 `/www/wwwroot/lill/backend/uploads/`，路径没变就不用改）。
4. 点「保存」。面板会自动 `nginx -t` 并重载；如果弹红色报错，说明语法有问题，此时旧配置已自动回滚，站不会挂。

保存后立刻验证（把域名换成自己的）：

```bash
curl -sI https://blog.example.com/themes/default/style.css | grep -i cache-control   # 期望 no-cache
curl -s -o /dev/null -w '%{http_code}\n' https://blog.example.com/themes/default/missing.js  # 期望 404
```

如果第一条返回的是 `max-age=43200`，说明 `^~` 被改掉了，主题改动会看不到。

#### 5.1.6 用「Node 项目」跑后端（不绑域名）

1. 「网站」→「Node 项目」→「添加Node项目」。
2. 按表填，**关键是「域名」留空**：

   | 字段 | 填写值 |
   |---|---|
   | 项目名称 | `lill_backend`（只允许字母数字下划线，不能带横线） |
   | 项目目录 | `/www/wwwroot/lill/backend` |
   | 启动选项 | 选 `start`（来自 `backend/package.json` 的 `scripts.start`）；没有下拉就填 `server.js` |
   | Node 版本 | `v24.21.0`（即 5.1.1 装的那个） |
   | 端口 | `3000`（**这个框只用于面板生成反代和端口占用校验，不会传给进程**，见下面第 3 步） |
   | 绑定外网 / 域名 | **不绑、留空**（绑了会生成整站反代 vhost，覆盖掉 5.1.4 的静态站） |
   | 运行用户 | `www` |
   | 开机自启 | 开 |

3. **把进程参数写进启动命令**，这是 5.1.6 最容易踩死的一步。宝塔生成的启动脚本长这样（可在 `/www/server/nodejs/vhost/scripts/<项目名>.sh` 看到）：

   ```bash
   PATH=/www/server/nodejs/v24.21.0/bin:...
   export PATH
   export NODE_PROJECT_NAME="lill_backend"
   cd /www/wwwroot/lill/backend
   nohup /www/server/nodejs/v24.21.0/bin/node /www/wwwroot/lill/backend/server.js &>> .../lill_backend.log &
   ```

   里面**只有 `node server.js`，没有 `PORT`**；同时它也不读 `ecosystem.config.cjs`。所以进程会用 [`backend/server.js`](../backend/server.js) 里 `parseInt(process.env.PORT) || 3000` 的默认值。3000 已被别的实例占着时，报的就是：

   ```
   Error: listen EADDRINUSE: address already in use 0.0.0.0:3000
   ```

   面板「环境变量」输入框无效：`mod/project/nodejs/nodeMod.py` 里 `run_env` 恒为空串，`get_run_env()` 只对 `get.env` 做了 `join` 而没有返回值。但 `.env` 不靠面板读取——`backend/server.js` 启动时自己解析 `backend/.env`，所以**宝塔 Node 项目同样只维护 `backend/.env` 一处**：

   - 把 `PORT=3001` 之类的值和 `JWT_SECRET` 写进 `backend/.env`，启动命令保持面板默认即可；
   - 进程里已存在的环境变量优先于 `.env`（服务端只在变量未定义时才采用 `.env` 的值），因此启动选项里另传 `env PORT=3001 node server.js` 同样有效。

   已实测：`nohup env PORT=3001 node server.js` 能正常监听 3001；而 `nohup PORT=3001 node server.js` 这种写法不生效。

4. PM2 的 `ecosystem.config.cjs` 不需要写进程参数；这些参数由 `backend/.env` 管理。若使用宝塔 Node 项目，需在启动命令中单独传参数：

   宝塔 Node 项目与 PM2 一样读 `backend/.env`；若想写在启动命令里，可用 `env PORT=3000 node server.js` 并追加 `HOST`、`DATA_DIR`、`UPLOAD_DIR`、`FRONTEND_URL` 或 `JWT_SECRET`。`JWT_SECRET` 留空时，首次启动会生成并保存到 `DATA_DIR/jwt-secret.txt`（权限 `0600`），之后重启复用。无论哪种启动方式，都不要把进程参数散落到 `ecosystem.config.cjs` 与启动脚本里。
5. 点「提交」启动，然后在「Node 项目」列表看状态，并点「日志」确认没有报错。终端验证：

   ```bash
   curl --fail http://127.0.0.1:3000/api/v1/install/status
   ```

   应当返回 `{"code":0,...,"installed":false,...}` 这类安装状态 JSON。

6. 后端固定监听 `0.0.0.0:3000`。宝塔「安全」和云厂商安全组**不要放行 3000**，只放行 80/443。

7. 端口 3000 如果被别的程序占了（面板会提示「指定端口已被其它应用占用」），先找出来停掉：

   ```bash
   ss -lntp | grep 3000
   ```

#### 5.1.7 申请 SSL

1. 「网站」→ 该域名 →「设置」→「SSL」→「Let's Encrypt」，勾选域名，文件验证，点「申请」。
2. 申请前确认域名已解析到本机、80 端口对公网可达。
3. 成功后在同一页打开「强制HTTPS」。

**顺序不能反**：先申请证书、再动伪静态。反过来时如果伪静态写错导致 nginx 起不来，证书验证的 80 端口也就不通了。

4. 访问 `https://blog.example.com/admin/` 进安装向导，填站点名、HTTPS 地址、管理员账号，完成初始化。

#### 5.1.8 验收

把域名换掉后逐条跑，最后一条期望 404：

```bash
curl --fail https://blog.example.com/api/v1/install/status
curl --fail 'https://blog.example.com/api/v1/site/bootstrap?path=%2F'
curl --fail 'https://blog.example.com/api/v1/posts?page=1&pageSize=10'
curl --fail https://blog.example.com/feed.xml
curl -I https://blog.example.com/themes/default/missing.js
```

再在浏览器确认：首页、文章页、后台登录、切换到另一个主题后颜色确实变了（验证 `/themes/` 的 no-cache 生效）、上传一张图片后 `/uploads/` 能打开。

#### 5.1.9 同一台服务器跑多个 lill 实例

一个 lill 实例默认占一个端口，但**不是「一台服务器只能一个」**：改 `PORT` 就能并存，已实测两个实例分别在 3001 / 3002 同时返回 200。约束只有三条：

1. **端口不能重复**：第二个实例 `PORT` 必须显式设成 3001 之类的值（写法见 5.1.6 第 3 步）。
2. **数据库不能共用**：每个实例要有自己的 `DB_PATH`，否则两个进程对同一个 SQLite 并发写，数据会错乱。
3. **上传目录不能共用**：`UPLOAD_DIR` 各自独立。

两个实例并行运行所需的最小配置（第二个实例）：

```bash
cd /www/wwwroot/lill2/backend
PORT=3001 \
DB_PATH=/www/wwwroot/lill2/backend/data/lill.db \
UPLOAD_DIR=/www/wwwroot/lill2/backend/uploads \
THEMES_DIR=/www/wwwroot/lill2/frontend/themes \
JWT_SECRET=各自独立的密钥 \
node server.js
```

对应的 Nginx 静态站点里，`location ^~ /api/` 的 `proxy_pass` 要指向自己的端口（`http://127.0.0.1:3001`），`/uploads/` 的 `alias` 指向自己的上传目录。

#### 宝塔常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板里搜不到「纯静态」站点类型 | 宝塔的「纯静态」只是 PHP 版本下拉里的 `php-00` 项，不是站点类型；`sites` 表里只有 PHP/Node/HTML/Proxy 等 | 建 HTML 项目，或建普通站点后在「网站目录」指向 `frontend/` |
| 搜不到「PM2 管理器」插件 | 新版面板已用「Node 项目」取代它 | 用 5.1.6 的 Node 项目，不绑域名 |
| 建 Node 项目后前台全 404 | Node 项目默认生成 `location / { proxy_pass ...; }` 整站反代 | 项目里把「绑定外网/域名」清空，重新生成配置 |
| `unknown directive "http2"` | Nginx 版本低于 1.25.1 | 升 Nginx，或把 vhost 里的 `http2 on;` 删掉 |
| 后台换了主题、前台没变化 | 伪静态用了普通前缀 `location /themes/`，被面板自带的 `(js|css)?$` 正则抢先 | 改成 `location ^~ /themes/` |
| `/sitemap.xml` 返回首页 HTML | 片段里漏了 `location = /sitemap.xml`，请求落到 `location /` 的 `index.html` 回退 | 重新粘贴完整片段并保存 |
| 上传大图 413 | 片段里 `client_max_body_size` 太小 | 调到 `50M` 或更大，保存后重载 |
| `Cannot find module 'node:sqlite'` | Node 项目用的 Node 版本低于 22.13 | Node 项目里把 Node 版本改成 24 那个 |
| 启动报 `EADDRINUSE ... 0.0.0.0:3000` | 面板「端口」框不传给进程；启动命令里没有 `PORT`，回了默认 3000 | 按 5.1.6 第 3 步把 `PORT=<自己的端口>` 写进 `package.json` 的 `start` 或启动选项 |
| 在 Node 项目里填了「环境变量」但不生效 | 面板 `run_env` 恒为空串，`get_run_env()` 只 join 不返回 | 环境变量一律写进启动命令；只靠 `ecosystem.config.cjs` 也不行（Node 项目不读它） |
| 建 Node 项目报「请先到模块管理中点击【一键安装项目模块】」 | 项目目录下没有 `node_modules` | 回 5.1.3 跑 `npm install --omit=dev` |
| 保存伪静态后站挂了 | 片段被改动过，`nginx -t` 失败 | 面板已自动回滚；删掉多余内容重贴原文件 |
| 页面报 `Unexpected token '<'` | JS/CSS 404 后回退成了 HTML | 确认片段里 `/themes/`、`/_astro/`、`/admin/` 三条 `^~` 规则都在 |
| 重启后登录失效 | 确认 `DATA_DIR/jwt-secret.txt` 在重启和迁移后仍保留，或在 `backend/.env` 中显式设置 `JWT_SECRET` |

### 5.2 1Panel

1. 准备 OpenResty 和满足要求的 Node 运行环境，按第 2 节安装程序。
2. 创建静态网站，选择实际映射到 `frontend/` 的目录。
3. 在 Node 运行环境或独立进程管理中启动后端，配置环境变量和持久化数据目录。
4. 按第 4 节配置上游与静态路由，申请并启用 HTTPS。

**容器中的 `127.0.0.1` 指向该容器自身。** OpenResty 与后端不在同一网络命名空间时，必须把示例中的上游地址（API 和 RSS 两处）改为代理可达的后端地址，例如共同容器网络中的服务名及端口，或实际可达的宿主机地址。不要假定宿主机回环地址在容器中也可用。

静态站点、上传文件需挂载到 OpenResty 可读的路径，`root` / `alias` 使用容器内路径。Node 安装目录、宿主机网关和网站目录取决于面板版本与部署方式，不能统一照抄某个 `/opt/1panel/...` 路径。验证代理应从其实际网络环境进行。

### 5.3 裸机

使用系统支持的方式安装 Node.js 24 LTS、Nginx、`zip`，源码部署另需 Git、pnpm、`rsync`。按第 2–4 节完成程序准备、PM2 和 Nginx 配置；发行版的站点配置位置及服务名以本机为准。

## 7. 升级与备份

### 升级

1. 阅读[发布说明](发布说明.md)和[更新日志](../CHANGELOG.md)，在新目录解压发布包，或检出指定版本并按源码步骤构建。
2. 先创建并下载数据库一致性快照和附件备份，另存进程配置及完整主题、插件目录。
3. 停止后端写入，按明确文件清单同步代码和静态产物；保留 `backend/data/`、`backend/uploads/`，以及自定义 `DB_PATH` / `UPLOAD_DIR` 对应目录、固定 `JWT_SECRET`、其他私有环境变量和 PM2 配置。
4. 保留所有已安装的第三方主题及插件；官方默认主题更新单独处理，已自行修改时先比较差异，保留其运行时缓存。静态产物同步继续排除 `/themes/`。
5. 在更新后的 `backend/` 安装生产依赖，重启后端，按第 6 节检查；失败时按已保存的程序和数据备份回退。

不要直接把压缩包解压到运行目录，也不要对项目或主题总目录使用无差别删除同步。不能依赖“发布包不带数据库”来保证私有配置和第三方扩展不被覆盖。

根目录的 `deploy.sh` 含维护者固定的服务器、部署路径、本地 Node/pnpm 路径和健康检查域名，只适用于维护者当前环境，**不是通用一键安装器**。普通部署使用本文步骤。

### 备份边界

后台「备份」使用实际数据库和附件路径创建 SQLite 一致性快照（包含 WAL 中已提交数据），校验成功后提供列表与下载；数据库 `.db` 和附件 `.zip` 分别下载，附件为空时不生成 ZIP。备份存放在数据库所在目录的 `backups/` 下，创建备份时会清理超过 30 天的备份产物，请另存异机副本。

运行中直接复制 `lill.db` 可能漏掉 WAL 数据。备份尚无一键恢复流程，也不承诺数据库与附件之间的原子快照；不包含磁盘上的主题、插件和私有配置，这些需单独保存。

附件打包需要系统 `zip`，期限为 120 秒；备份请求后端期限为 150 秒，`/api/` 反向代理应保留 `proxy_read_timeout 160s`，普通 API 后端期限仍为 20 秒。

### 维护命令

```bash
pm2 list
pm2 logs lill-backend --lines 50
pm2 restart lill-backend
```

变更进程环境变量后，按实际托管方式重新加载配置；PM2 可重新加载已配置的 `ecosystem.config.cjs` 并 `pm2 save`。固定密钥正常升级时保持不变，泄露时应立即轮换，现有登录会失效。

## 8. 常见问题

| 现象 | 检查 |
|---|---|
| `node:sqlite` 无法加载 | 确认进程实际使用 Node 24 LTS 或至少 22.13.0，不能只看终端的 `node -v` |
| API 502 | 查进程日志、端口和代理可达地址；容器中尤其要核对网络 |
| 页面白屏或 `Unexpected token '<'` | 检查静态文件是否落在 `frontend/`、资源请求是否错误回退到 HTML |
| 自定义永久链接打不开 | 保留 `/index.html` 通用回退，确认 bootstrap 收到实际路径 |
| RSS 返回 API 不存在 | `/feed.xml` 必须代理到 `/api/v1/feed` |
| 切主题后仍是旧样式 | 删除 `/theme.js` 的主题专属 alias，检查静态根目录与后端是否共享同一主题树 |
| 上传或备份失败 | 检查实际目录权限、磁盘空间、系统 `zip`、上传体积和代理超时 |
| 重启后登录失效 | 确认固定 `JWT_SECRET` 已写入实际运行配置 |
| 面板终端找不到 Node | 使用面板提供的终端或实际 Node 可执行文件路径，不假定所有面板安装目录一致 |

功能差距与限制见 [Typecho 1.3 功能对照](Typecho1.3功能对照.md)，不应将部署成功理解为已全面实现 Typecho 功能。
