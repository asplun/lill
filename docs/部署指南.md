# lill 部署指南

> 本文覆盖 **宝塔面板**、**1Panel 面板** 和 **裸机手动部署** 三种方式。
> 部署架构：Nginx/OpenResty 提供前端静态文件 + 反向代理 `/api/` 到 Node 后端（PM2 守护）。

## 0. 通用前置要求

### 0.1 服务器

| 项目 | 要求 |
|---|---|
| 系统 | Linux（CentOS 7+ / Ubuntu 20.04+ / Debian 10+） |
| 内存 | ≥ 1 GB（推荐 2 GB） |
| 磁盘 | ≥ 5 GB |
| 架构 | x86_64 / ARM64 均可 |

### 0.2 软件版本

| 软件 | 版本 | 说明 |
|---|---|---|
| **Node.js** | **≥ 22（推荐 24 LTS）** | 必须！后端使用 `node:sqlite`，Node 18/20 不支持 |
| Nginx / OpenResty | 任意较新版本 | 面板自带即可 |
| PM2 | 最新版 | 进程守护 |
| Git | 任意 | 拉取代码（也可手动上传） |

> ⚠️ **Node.js 版本是最大的坑**：低于 22 会报 `Cannot find module 'node:sqlite'`。

### 0.3 域名与端口

- 一个已解析到服务器的域名（如 `blog.example.com`）
- 后端监听 `127.0.0.1:3000`（不对外暴露，由 Nginx 反代）
- 面板安全组/防火墙需放行 `80`、`443`

### 0.4 部署目录约定

本文统一使用：

```
/www/wwwroot/lill/            # 站点根目录（宝塔默认）
├── backend/                  # Node 后端
└── frontend/
    ├── dist/                 # 构建产物（Nginx root 指向这里）
    └── ...
```

> 1Panel 用户可换成 `/opt/1panel/www/sites/lill/`，下文命令自行替换路径。
> 
> 💡 **实际部署路径**：根据你的服务器配置，实际路径可能不同。本文以宝塔默认路径 `/www/wwwroot/lill/` 为例，1Panel 默认路径为 `/opt/1panel/www/sites/lill/`。

## 1. 宝塔面板部署

> 💡 **新手友好**：本章以 **面板可视化操作** 为主线，全程只有「构建前端」需要执行一次命令（可直接复制粘贴），其余步骤都在面板点击完成。
> 想手动改 Nginx 配置的进阶用户，见 [1.10 进阶：手动配置 Nginx](#110-进阶手动配置-nginx)。

### 1.1 安装宝塔面板

若尚未安装，参考官方文档：<https://www.bt.cn/new/download.html>

安装完成后登录面板。

### 1.2 安装必要软件（可视化）

打开「软件商店」，搜索并安装：

| 软件 | 用途 | 是否必需 |
|---|---|---|
| **Nginx** | Web 服务器（推荐 1.24+） | ✅ 必需 |
| **Node.js 版本管理器** | 安装 Node 22/24 | ✅ 必需 |
| **PM2 管理器** | 可视化守护后端进程 | ✅ 必需 |
| **Git** | 拉取代码（也可用文件上传） | 可选 |

**安装 Node.js：**

打开「Node.js 版本管理器」→ 安装 **Node 24 LTS**（或 22）→ 安装后点击「命令行版本」设为默认。

> ⚠️ **Node.js 版本是最大的坑**：必须 ≥ 22，低于 22 会报 `Cannot find module 'node:sqlite'`。

**PM2 管理器：**

在「软件商店」安装 **PM2 管理器** 后，可在面板里可视化启动、重启、查看日志，无需敲命令。

### 1.3 上传代码（可视化）

**方式 A：Git 拉取（推荐）**

若已安装 Git，用宝塔「终端」执行一次：

```bash
cd /www/wwwroot
git clone https://github.com/asplun/lill.git
cd lill
```

**方式 B：面板上传（零命令）**

1. 把项目打包成 `.zip`（或从 [GitHub Releases](https://github.com/asplun/lill/releases) 下载）
2. 宝塔「文件」→ 进入 `/www/wwwroot/` → 上传 → 解压
3. 把解压出的目录重命名为 `lill`

### 1.4 构建前端（唯一需要命令的一步）

lill 前端是 Astro 静态站，必须构建一次生成 `frontend/dist/`。**二选一**：

**方式 A：服务器构建（复制粘贴即可）**

宝塔「终端」中粘贴执行：

```bash
cd /www/wwwroot/lill/frontend
npm install -g pnpm
pnpm install && pnpm run build
```

> 💡 命令虽长，但只需执行这一次。构建完成后 `frontend/dist/` 会出现 `index.html`、`_astro/`、`admin/` 等文件。

**方式 B：本地构建后上传（完全不碰服务器命令）**

1. 在本地电脑安装 Node 22+ 与 pnpm
2. 本地执行 `pnpm install && pnpm run build`
3. 把本地 `frontend/dist/` 整个目录上传到服务器 `/www/wwwroot/lill/frontend/dist/`

> 📌 以后每次更新主题/前端，都要重新构建并覆盖 `dist/`。后台「主题」切换只改数据库，不触发构建。

### 1.5 创建静态网站（可视化）

1. 宝塔面板 →「网站」→「添加站点」
2. 填写：
   - **域名**：`blog.example.com`
   - **根目录**：`/www/wwwroot/lill/frontend/dist`
   - **FTP**：不创建
   - **数据库**：不创建（lill 使用 SQLite）
   - **PHP 版本**：纯静态
3. 提交

> ⚠️ **不要选「Node 项目」**：宝塔 Node 项目会把所有请求反代到 Node，而 lill 后端只处理 `/api/`，前台静态页面会 404。lill 必须用「纯静态」站点 + 反向代理。

### 1.6 配置反向代理（可视化，无需改配置文件）

1. 「网站」→ 点击站点名 →「反向代理」→「添加反向代理」
2. 依次添加 **3 条**：

| 代理名称 | 代理目录 | 目标 URL |
|---|---|---|
| `lill-api` | `/api` | `http://127.0.0.1:3000` |
| `lill-uploads` | `/uploads` | `http://127.0.0.1:3000` |
| `lill-feed` | `/feed.xml` | `http://127.0.0.1:3000` |

3. 每条都保持默认「发送域名 `$host`」，提交即可。

> 💡 宝塔会自动生成对应的 `location` 配置并重载 Nginx，不用手动编辑。
> 若想用 Nginx 直接读上传文件（性能更好），见 [1.10](#110-进阶手动配置-nginx)。

### 1.7 启动后端（可视化：PM2 管理器）

1. 「软件商店」→ 打开已安装的 **PM2 管理器**
2. 点击「添加项目」，填写：

| 字段 | 值 |
|---|---|
| **项目名称** | `lill-backend` |
| **启动文件** | `/www/wwwroot/lill/backend/server.js` |
| **运行目录** | `/www/wwwroot/lill/backend` |
| **Node 版本** | 选择已安装的 22 / 24 |
| **环境变量** | 见下方 |

**环境变量（重要）：**

| 变量名 | 值 |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | `3000` |
| `HOST` | `127.0.0.1` |
| `JWT_SECRET` | 一段 ≥ 32 位的随机字符串 |

> 🔐 **JWT_SECRET 怎么来**：用任意随机字符串生成工具（或用密码管理器）生成 64 位随机串粘贴进去即可。
> **设置后不要更改**，否则所有已登录用户会被登出；一旦泄露应立即更换。

3. 保存并「启动」。PM2 管理器会显示进程状态、CPU/内存、实时日志。

> 💡 **如果你的 PM2 管理器版本没有「环境变量」输入框**：用宝塔「文件」双击打开 `backend/ecosystem.config.js`，把 `JWT_SECRET` 一行取消注释并填入随机串；然后在 PM2 管理器中把「启动文件」改为 `ecosystem.config.js` 启动即可。

**验证后端：**

浏览器访问 `http://127.0.0.1:3000/api/v1/install/status`（需在服务器上），或看 PM2 日志无报错即可。

### 1.8 申请 SSL 证书（可视化）

「网站」→ 站点 →「SSL」→「Let's Encrypt」→ 勾选域名 → 申请 → 申请成功后打开「强制 HTTPS」。

### 1.9 完成安装

浏览器访问：

```
https://blog.example.com/admin/
```

会自动跳转到安装向导：

1. **环境检查** — 确认全部通过
2. **站点信息** — 站点名称、描述、地址（填 `https://blog.example.com`）
3. **管理员** — 用户名、密码、邮箱
4. **完成** — 自动创建默认主题和 Hello World 文章

安装完成后即可进入后台写作。

### 1.10 进阶：手动配置 Nginx

> 已按 [1.6](#16-配置反向代理可视化无需改配置文件) 用可视化反向代理的用户**可跳过本节**。以下为完整配置模板，适合需要精细控制或想让 Nginx 直读上传文件的用户。

进入「网站」→ 点击站点名 →「配置文件」，**整体替换**为以下内容（把域名和路径改成你自己的）。

> 📎 仓库内也提供了可直接复制的模板文件：[`deploy/nginx.conf.example`](../deploy/nginx.conf.example)

```nginx
server {
    listen 80;
    server_name blog.example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name blog.example.com;

    # SSL 证书路径（宝塔申请证书后自动生成，若用宝塔一键 SSL 可省略这两行）
    ssl_certificate     /www/server/panel/vhost/cert/blog.example.com/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/blog.example.com/privkey.pem;

    root /www/wwwroot/lill/frontend/dist;
    index index.html;

    # ── 后端 API 反向代理 ──
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 50M;          # 媒体上传大小上限
    }

    # ── 上传文件由 Nginx 直接读取（性能更好） ──
    location /uploads/ {
        alias /www/wwwroot/lill/backend/uploads/;
        expires 30d;
        add_header Cache-Control "public";
        access_log off;
    }

    # ── 动态路由回退到各自的静态壳 ──
    location /post/     { try_files $uri $uri/ /post/index.html; }
    location /category/ { try_files $uri $uri/ /category/index.html; }
    location /tag/      { try_files $uri $uri/ /tag/index.html; }
    location /page/     { try_files $uri $uri/ /page/index.html; }

    # ── RSS Feed ──
    location = /feed.xml {
        proxy_pass http://127.0.0.1:3000/api/v1/feed;
        proxy_set_header Host $host;
    }

    # ── 前端静态文件 ──
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

保存后重载 Nginx（宝塔会自动重载）。

> **未配置 HTTPS 时**：删掉第一个 `server{}` 跳转块，并把第二个块的 `listen 443 ssl;` 改为 `listen 80;`，同时删掉两行 `ssl_certificate`。

## 2. 1Panel 面板部署

### 2.1 安装 1Panel

参考官方文档：<https://1panel.cn/docs/installation/online_installation/>

### 2.2 安装必要应用

进入 1Panel →「应用商店」，安装：

| 应用 | 用途 |
|---|---|
| **OpenResty** | Web 服务器（1Panel 默认用它替代 Nginx） |
| **Node.js** | 运行环境（选择 **22 或 24**） |

> 1Panel 的 Node.js 应用通常安装在 `/opt/1panel/runtime/node/` 下，安装后在终端可直接使用 `node` / `npm`。

**安装 PM2：**

1Panel 的「终端」或 SSH 中执行：

```bash
npm install -g pm2
pm2 -v
```

> ⚠️ **常见问题**：若提示 `node: command not found`，执行 `source /etc/profile` 或重新打开终端。1Panel 的 Node.js 通常安装在 `/opt/1panel/runtime/node/current/bin/`，确保该路径在 `$PATH` 中。

### 2.3 上传代码

```bash
mkdir -p /opt/1panel/www/sites/lill
cd /opt/1panel/www/sites/lill
git clone https://github.com/asplun/lill.git .
```

或用 1Panel「文件」功能上传压缩包后解压到该目录。

### 2.4 构建前端

```bash
cd /opt/1panel/www/sites/lill/frontend
npm install -g pnpm
pnpm install
pnpm run build
```

### 2.5 创建网站

1Panel →「网站」→「创建网站」：

| 字段 | 值 |
|---|---|
| **类型** | 静态网站 |
| **主域名** | `blog.example.com` |
| **网站目录** | `/opt/1panel/www/sites/lill/frontend/dist` |
| **端口** | 80（外部端口，后续开 SSL 后自动处理） |

> 若 1Panel 要求先建目录，可直接填 `frontend/dist` 的绝对路径，创建后它会自动接管。

### 2.6 配置反向代理

1Panel 提供两种方式，**任选其一**：

#### 方式 A：图形化反向代理（推荐）

进入网站 →「反向代理」→「创建反向代理」：

| 字段 | 值 |
|---|---|
| **名称** | `lill-api` |
| **代理地址** | `http://127.0.0.1:3000` |
| **匹配规则** | `/api`（前缀匹配） |

再创建一个用于 RSS：

| 名称 | 代理地址 | 匹配规则 |
|---|---|---|
| `lill-feed` | `http://127.0.0.1:3000/api/v1/feed` | `/feed.xml` |

#### 方式 B：直接编辑配置文件

进入网站 →「配置文件」，在 `server { }` 块内加入以下内容。

> 💡 **1Panel 配置说明**：1Panel 使用 OpenResty（Nginx 增强版），配置语法与 Nginx 完全兼容。如果选择整体替换，注意保留 1Panel 自动生成的 SSL 证书路径。

```nginx
# 后端 API
location /api/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 50M;
}

# 上传文件
location /uploads/ {
    alias /opt/1panel/www/sites/lill/backend/uploads/;
    expires 30d;
    add_header Cache-Control "public";
    access_log off;
}

# 动态路由回退
location /post/     { try_files $uri $uri/ /post/index.html; }
location /category/ { try_files $uri $uri/ /category/index.html; }
location /tag/      { try_files $uri $uri/ /tag/index.html; }
location /page/     { try_files $uri $uri/ /page/index.html; }

# RSS
location = /feed.xml {
    proxy_pass http://127.0.0.1:3000/api/v1/feed;
    proxy_set_header Host $host;
}
```

保存并重载 OpenResty。

### 2.7 启动后端

```bash
cd /opt/1panel/www/sites/lill/backend

# 生成 JWT 密钥并填入 ecosystem.config.js
openssl rand -hex 32

pm2 start ecosystem.config.js
pm2 save
pm2 startup
```

> ⚠️ **安全提醒**：JWT 密钥一旦设置，**不要更改**，否则所有已登录用户需要重新登录。如果密钥泄露，应立即更换并通知用户重新登录。

**验证：**

```bash
curl http://127.0.0.1:3000/api/v1/install/status
```

### 2.8 申请 SSL

1Panel →「网站」→ 站点 →「HTTPS」→「申请证书」→ 选择 Let's Encrypt → 勾选域名 → 申请并启用。

启用后开启「强制 HTTPS」。

### 2.9 完成安装

访问 `https://blog.example.com/admin/` 走完安装向导（同 [1.9](#19-完成安装)）。

## 3. 裸机手动部署

不使用面板时，用系统包管理器安装即可。

```bash
# 1. 安装 Node.js 22/24（以 NodeSource 为例）
curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
apt install -y nodejs nginx git

# 2. 安装 PM2 和 pnpm
npm install -g pm2 pnpm

# 3. 拉取代码
mkdir -p /var/www && cd /var/www
git clone https://github.com/asplun/lill.git
cd lill

# 4. 构建前端
cd frontend && pnpm install && pnpm run build

# 5. 启动后端
cd ../backend
openssl rand -hex 32     # 填入 ecosystem.config.js
pm2 start ecosystem.config.js && pm2 save && pm2 startup
```

Nginx 站点配置：把 `/etc/nginx/sites-available/lill` 指向 [1.10 的配置模板](#110-进阶手动配置-nginx)（路径改为 `/var/www/lill/...`），然后：

```bash
ln -s /etc/nginx/sites-available/lill /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

## 4. 升级与维护

### 4.1 升级到最新版

```bash
cd /www/wwwroot/lill          # 换成你的实际路径

# 备份数据库（重要！）
cp backend/data/lill.db backend/data/lill-backup-$(date +%Y%m%d).db

# 拉取更新
git pull

# 重新构建前端
cd frontend && pnpm install && pnpm run build

# 重启后端
cd ../backend && pm2 restart lill-backend
```

### 4.2 常用 PM2 命令

```bash
pm2 list                    # 查看进程
pm2 logs lill-backend       # 实时日志
pm2 restart lill-backend    # 重启
pm2 stop lill-backend       # 停止
pm2 delete lill-backend     # 删除
pm2 monit                   # 资源监控
```

### 4.3 数据备份

- **数据库**：`backend/data/lill.db`（单文件，直接复制即可）
- **上传文件**：`backend/uploads/`
- **主题**：`frontend/themes/`

后台「备份」菜单也可一键生成数据库副本。

## 5. 常见问题排查

### ❌ `Cannot find module 'node:sqlite'`

Node.js 版本过低。升级到 **22+（推荐 24）**：

```bash
node -v
# 若 < 22，用面板的 Node 版本管理器切换，或重新安装
```

### ❌ 后台能打开但接口全部 502

后端没启动或端口不对：

```bash
pm2 list                          # 看 lill-backend 是否 online
curl http://127.0.0.1:3000/api/v1/install/status
pm2 logs lill-backend --lines 50  # 看报错
```

### ❌ 前台正常，但 `/admin/` 白屏或样式错乱

前端构建产物不完整。重新构建并确认 `frontend/dist/` 下有 `_astro/` 目录：

```bash
cd frontend && pnpm run build && ls dist/_astro/
```

### ❌ 访问 `/admin/` 一直转圈

通常是 `/api/v1/auth/me` 返回 404 或 502。检查：

1. Nginx 是否配置了 `location /api/` 反代
2. 后端是否运行
3. 是否被浏览器缓存（强制刷新 `Ctrl+Shift+R`）

### ❌ 上传图片失败

1. Nginx 的 `client_max_body_size` 是否够大（模板中为 50M）
2. `backend/uploads/` 目录是否有写权限：

```bash
chown -R www:www /www/wwwroot/lill/backend/uploads
chmod -R 755 /www/wwwroot/lill/backend/uploads
```

### ❌ 重启后需要重新登录

`JWT_SECRET` 未设置，每次启动都生成随机密钥。按 [1.7 启动后端](#17-启动后端可视化pm2-管理器) 在 PM2 管理器的环境变量中设置固定值。

### ❌ 安装向导提示「站点已安装」

数据库中已存在用户。若要全新安装：

```bash
pm2 stop lill-backend
mv backend/data/lill.db backend/data/lill-old.db   # 备份而非删除
pm2 start lill-backend
```

### ❌ 1Panel 中 `node: command not found`

Node 环境变量未加载：

```bash
source /etc/profile
# 或直接用绝对路径
/opt/1panel/runtime/node/current/bin/node -v
```

### ❌ 宝塔 PM2 管理器无法启动后端

检查 Node.js 版本是否正确：

```bash
# 查看当前 Node 版本
node -v

# 如果版本不对，在宝塔「Node.js 版本管理器」中切换
# 或手动指定路径
/www/server/nodejs/v22.0.0/bin/node -v
```

### ❌ 1Panel 反向代理后 API 返回 502

检查后端是否运行：

```bash
pm2 list
curl http://127.0.0.1:3000/api/v1/install/status
```
