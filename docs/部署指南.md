# lill v1.3.2 部署指南

部署结构：Nginx / OpenResty 提供 `frontend/` 静态文件，将 `/api/` 转发给 Node 后端。后端使用原生 `node:http` 和内置 `node:sqlite`，无需外部数据库服务。

[发布说明](发布说明.md) · [更新日志](../CHANGELOG.md) · [API 文档](API文档.md)

## 1. 环境与目录

| 项目 | 要求 |
|---|---|
| Node.js | 推荐 24 LTS，最低 22.13.0；无需 `--experimental-sqlite` |
| Nginx / OpenResty | 提供静态站点、API 反向代理和 HTTPS |
| 进程管理 | 面板 Node 项目管理或 PM2，单实例运行 |
| 系统工具 | 附件备份需要 `zip`；源码构建同步需要 `rsync` |
| 包管理器 | 后端可用 npm 或 pnpm；本文源码前端构建使用 pnpm |

本文以 `/www/wwwroot/lill` 为示例路径。宝塔、1Panel、裸机及容器的实际目录和运行用户各不相同，请按本机配置替换；面板内安装的 Node 也不一定进入宿主机终端的 `PATH`。

```text
lill/
├── backend/
│   ├── server.js
│   ├── ecosystem.config.cjs
│   ├── data/                  # 默认数据库 lill.db、backups/，运行后产生
│   ├── uploads/               # 默认附件目录，运行后产生
│   └── plugins/
└── frontend/                  # Nginx root
    ├── index.html             # 发布包已包含；源码构建后同步
    ├── admin/
    ├── _astro/
    └── themes/default/        # 保留完整主题，含 backend/ 扩展
```

同机部署可用 `127.0.0.1:3000` 访问后端。**当前源码固定监听 `0.0.0.0`，未读取 `HOST` 环境变量**；请通过防火墙、安全组或容器端口映射限制 3000 端口，仅允许代理访问，对公网开放 80/443。

## 2. 准备程序

以下两种方式任选一种，均在新目录准备，勿直接解压覆盖运行中的站点。

### 2.1 使用发布包

从 [GitHub Releases](https://github.com/asplun/lill/releases) 下载：

- `lill-v1.3.2.zip`
- `lill-v1.3.2.tar.gz`

两种包解压后均为顶层 `lill/`，包含仓库跟踪的源码及预构建静态文件。静态文件直接放在 `frontend/`，包内没有 `frontend/dist/`；仅包含默认主题及其后端扩展、内置插件，不包含数据库、上传文件、`node_modules`、密钥或第三方主题。

```bash
# 示例：压缩包已上传到 /www/wwwroot，且该目录下尚无 lill/
cd /www/wwwroot
tar -xzf lill-v1.3.2.tar.gz
cd lill/backend
npm install --omit=dev
```

ZIP 可通过面板解压。使用 pnpm 时，将后端依赖安装命令改为 `pnpm install --prod --frozen-lockfile`。**发布包不需要安装前端依赖或执行 Astro 构建**。

GitHub 自动生成的 `Source code` 归档没有预构建静态文件，需按源码流程构建。

### 2.2 使用源码

```bash
cd /www/wwwroot
git clone https://github.com/asplun/lill.git
cd lill
git checkout v1.3.2
cd backend
npm install --omit=dev
# 后端也可使用：pnpm install --prod --frozen-lockfile
cd ../frontend
pnpm install --frozen-lockfile
pnpm run build
rsync -a --exclude='/themes/' dist/ ./
```

必须安装两端依赖，再构建并同步静态文件。`frontend/dist/` 是构建暂存目录，Nginx 根目录仍指向 `frontend/`；排除 `themes/`，避免用缺少后端扩展的构建副本覆盖完整主题。可在本地完成构建后上传同步后的文件，无需在生产服务器构建。

维护者生成发布包的命令如下，需安装 Python 3、Node.js 和 pnpm，在源码根目录执行：

```bash
python3 scripts/package-release.py --ref v1.3.2 --output /tmp/lill-release
```

[打包脚本](../scripts/package-release.py)从指定 Git 引用导出干净源码，仅构建默认主题，再将构建输出合并到包内 `frontend/`；不会把 `dist/` 作为发布目录。安装者可直接使用其输出的两个压缩包，并通过 `SHA256SUMS` 校验下载完整性，详见[发布说明](发布说明.md)。

## 3. 启动后端

先生成一次密钥，将结果保存在面板环境变量或服务器私有进程配置中：

```bash
openssl rand -hex 32
```

| 环境变量 | 设置 |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | 默认 `3000` |
| `JWT_SECRET` | 固定随机密钥；重启和升级时保留，勿提交到仓库 |
| `FRONTEND_URL` | 站点 origin，如 `https://blog.example.com`，用于 CORS |
| `DB_PATH` | 可选，建议绝对路径；默认 `backend/data/lill.db` |
| `UPLOAD_DIR` | 可选，建议绝对路径；默认 `backend/uploads/` |

进程用户需要读写数据库、附件和备份目录；后台安装主题或插件时，也需要对应目录的写权限。不要将整个项目设为所有人可写。

使用 PM2 时，在服务器私有的 `backend/ecosystem.config.cjs` 的 `env` 中填写上述配置，再启动：

```bash
cd /www/wwwroot/lill/backend
pm2 start ecosystem.config.cjs
pm2 save
curl --fail http://127.0.0.1:3000/api/v1/install/status
```

若环境没有 PM2，可先用 `npm install -g pm2` 安装，或直接使用面板进程管理。PM2 的开机启动按 `pm2 startup` 输出配置；面板托管时使用面板自带的开机启动机制。

临时调试可在已配置环境变量的终端运行 `node server.js`。Node 后端不提供前台或后台静态页面，完整访问还需下一节的静态站点配置。

## 4. Nginx / OpenResty

创建纯静态站点，根目录设为 `/www/wwwroot/lill/frontend`。以下为 HTTP 示例；按实际域名、目录和上游地址调整，合并到已有站点配置时保留面板生成的证书、验证目录等内容，避免重复的 `location`。完整站点模板见 [deploy/nginx.conf.example](../deploy/nginx.conf.example)。

```nginx
server {
    listen 80;
    server_name blog.example.com;
    root /www/wwwroot/lill/frontend;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 160s;
        client_max_body_size 50M;
    }

    # RSS 必须映射到真实 API，不能将 /feed.xml 原样转发到后端根路径。
    location = /feed.xml {
        proxy_pass http://127.0.0.1:3000/api/v1/feed;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 站点地图与 robots 由后端生成，必须映射到真实 API；否则 /sitemap.xml 会落到首页 HTML。
    location = /sitemap.xml {
        proxy_pass http://127.0.0.1:3000/api/v1/sitemap.xml;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /robots.txt {
        proxy_pass http://127.0.0.1:3000/robots.txt;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 自定义 UPLOAD_DIR 时同步调整；容器中必须挂载到代理可读路径。
    location ^~ /uploads/ {
        alias /www/wwwroot/lill/backend/uploads/;
        expires 30d;
    }

    # 完整主题需留在磁盘，但不对外提供服务端源码与依赖。
    location ~ ^/themes/[^/]+/(backend|node_modules)(/|$) { return 404; }
    location /themes/ {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }
    location ^~ /_astro/ {
        try_files $uri =404;
        add_header Cache-Control "public, max-age=2592000, immutable";
    }
    location = /api.js {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }
    location = /theme.js {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }
    location ~ ^/admin/.+\.(css|js|map|svg|png|ico|woff2?)$ {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }

    # 源码部署与发布包均可能保留这些文件，不作为站点资源提供。
    location ~ ^/(src|public|dist|node_modules)(/|$) { return 404; }
    location ~ ^/(package(-lock)?\.json|pnpm-lock\.yaml|pnpm-workspace\.yaml|astro\.config\.mjs)$ { return 404; }
    location ~ (^|/)\.(?!well-known(/|$)) { return 404; }

    location /admin/ {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /admin/index.html;
    }
    location /post/     { try_files $uri $uri/ /post/index.html; }
    location /category/ { try_files $uri $uri/ /category/index.html; }
    location /tag/      { try_files $uri $uri/ /tag/index.html; }
    location /page/     { try_files $uri $uri/ /page/index.html; }
    location /search/   { try_files $uri $uri/ /search/index.html; }
    location /archive/  { try_files $uri $uri/ /archive/index.html; }

    # 自定义永久链接由通用外壳携带实际 pathname 请求 bootstrap。
    location / {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /index.html;
    }
}
```

保存前通过面板或 `nginx -t` 校验，再重载对应 Nginx / OpenResty 实例。通过面板或证书工具配置 HTTPS；证书路径以实际安装为准，启用后将 HTTP 跳转到 HTTPS。

静态资源缺失应返回 404，不能返回首页 HTML。`/theme.js` 是通用引擎，不要 alias 到某个主题脚本。自定义内容路径通过 `/index.html` 回退，缺失内容由 bootstrap API 返回 404；静态外壳本身可能仍返回 HTTP 200，不属于 SSR 状态保证。

附件也可由后端提供 `/uploads/`，但当前后端仅允许部分图片类型；如需完整附件下载，优先使用上面的 Nginx 文件映射。

## 5. 面板与裸机配置

<!-- baota:start -->
### 5.1 宝塔面板（手把手）

本节以 Linux 服务器、宝塔面板、域名 `blog.example.com`、程序目录 `/www/wwwroot/lill` 为例，从空服务器部署 lill v1.3.2。步骤菜单以宝塔常见版本为准；若菜单文字略有差异，按同名功能进入。先准备好已解析到服务器公网 IP 的域名，并确保云厂商安全组允许入站 TCP 80、443；不要开放后端 3000 端口。

#### 5.1.1 安装宝塔面板

1. 在浏览器打开宝塔官网 [https://www.bt.cn/](https://www.bt.cn/)，进入「Linux 面板」下载页，按服务器发行版选择官方安装命令。
2. SSH 登录服务器，以有 sudo 权限的账号执行官网当前提供的安装命令；按提示确认安装，等待命令结束。不要从非官方网页复制安装脚本。
3. 安装结束后，保存终端显示的面板地址、用户名和初始密码。浏览器打开面板地址并登录，首次进入按向导设置面板账号密码；不要把初始凭据发到公开聊天或提交进仓库。
4. 如云厂商安全组或系统防火墙拦截面板端口，仅按宝塔页面显示的端口配置管理访问；面板管理端口不等于网站端口，网站仍只需 80/443 对公网开放。

#### 5.1.2 安装运行软件并确认 Node 版本

1. 登录面板，点左侧「软件商店」→「运行环境」。搜索并安装 Nginx，选择 **1.24 或更新版本**；点击「安装」，等待状态显示运行中。
2. 在「软件商店」搜索「Node.js 版本管理器」，点击「安装」。安装完成后打开管理页，选择 Node.js 24 LTS 并安装；再点该版本旁的「命令行版本」或「设为命令行版本」，使面板终端与项目管理器使用正确版本。
3. 在面板左侧「终端」打开服务器终端，执行 `node -v`。结果必须是 `v24...`，或至少 `v22.13.0`；若命令不存在或版本较低，回到版本管理器选对版本并设为命令行版本，再重新打开终端验证。Node 版本不够会导致后端报 `Cannot find module 'node:sqlite'`。
4. 在「软件商店」搜索并安装「PM2 管理器」，用于单独托管后端进程；Git 对上传发布包不是必需项，需要从源码克隆时再安装。

#### 5.1.3 上传并解压发布包

1. 在本机浏览器打开 [lill GitHub Releases](https://github.com/asplun/lill/releases)，下载 `lill-v1.3.2.zip`。这是已含预构建前端静态文件的发布包，不要下载 GitHub 自动生成的 `Source code` 归档作为即用包。
2. 面板点「文件」→进入 `/www/wwwroot/`。若目录不存在，使用文件管理器新建目录 `wwwroot`。点「上传」选择 `lill-v1.3.2.zip`，等待上传完成。
3. 在文件列表选中压缩包，点击「解压」；解压目录选 `/www/wwwroot/`。确认生成 `/www/wwwroot/lill/`，里面能看到 `backend/`、`frontend/` 和 `deploy/`。如果压缩包解出多一层目录，在文件管理器调整目录名，使项目根准确为 `/www/wwwroot/lill`。
4. 发布包的前端文件已直接位于 `frontend/`；不要将 Nginx 根目录指向前端构建暂存目录，也不要在服务器执行 Astro 构建。

#### 5.1.4 安装后端依赖

1. 点面板「终端」，执行以下命令安装生产依赖：

   ```bash
   cd /www/wwwroot/lill/backend && npm install --omit=dev
   ```

2. 等待命令完成并返回 shell 提示符；若出现权限错误，先确认终端用户对程序目录有读取权限，不要用 `chmod -R 777` 放开整个项目。
3. 发布包前端已预构建在 `frontend/`，无需安装前端依赖，不要运行 `pnpm install`、Astro 或前端构建命令。

#### 5.1.5 创建纯静态站点

1. 在面板点「网站」→「添加站点」。域名栏填写 `blog.example.com`（替换为自己的域名），根目录填写 `/www/wwwroot/lill/frontend`。
2. 站点类型选择「静态」或「纯静态」，不要选择 Node 项目；本教程由 Nginx 直接提供前端静态文件，后端将由 PM2 单独启动。**不要选 Node 项目**：它会把整站反向代理到 Node，导致前台静态页面 404。
3. FTP、数据库选项均不勾选（若界面强制显示可选项，保持关闭）；本应用使用 SQLite，不需要 MySQL，也不需要面板代建数据库。
4. 点击「提交」创建站点。到「网站」列表确认域名对应站点已创建，记录其配置文件入口。

#### 5.1.6 整体替换 Nginx 配置

1. 在「文件」打开 `/www/wwwroot/lill/deploy/nginx.conf.example`。复制该模板全文；它是本项目 Nginx 配置唯一真相。本节不重复粘贴第二份配置，具体路由和配置说明见[第 4 节](#4-nginx--openresty)。
2. 回到「网站」列表，找到 `blog.example.com`，点「设置」→「配置文件」。**先把当前配置全文复制到安全位置备份**，确认备份可找回；再选中原配置全部内容，用模板全文替换，不要只把几段 `location` 追加进去。
3. 在新配置中按下面的替换表逐项修改模板示例值，其他路由、代理和安全规则保持原样：

   | 模板中的值 | 替换为 / 检查方式 |
   |---|---|
   | `blog.example.com` | 你已解析到本服务器的域名；所有出现位置都替换一致 |
   | `/www/wwwroot/lill` | 实际项目根目录；`root` 应为该目录下的 `frontend` |
   | `ssl_certificate` 与 `ssl_certificate_key` 两行 | 先完成 5.1.8 申请证书后，填入宝塔显示的完整链证书和私钥绝对路径；不要猜路径或删掉这两行 |
   | `alias .../backend/uploads/` | 对应实际项目根目录下 `backend/uploads/`，保留末尾斜杠 |
   | `proxy_pass http://127.0.0.1:3000` | 同机部署保持不变；后端与 Nginx 同机时使用回环地址 |

4. 点击「保存」后，在配置页或 Nginx 管理页点「配置测试」；测试失败时不要重载，按错误提示修正，必要时恢复刚才备份的原配置。测试通过后点击「重载配置」。模板含 HTTPS 证书路径；证书尚未申请时可先保存备份并继续下一步，申请证书后立即填入宝塔实际证书路径、测试并重载，再启用 HTTPS。
5. 模板的 `/api/`、`/feed.xml`、`/sitemap.xml`、`/robots.txt`、`/uploads/` 和前端路由规则不可遗漏。不要另外添加整站 Node 反代，也不要把根目录指向构建暂存目录。

#### 5.1.7 用 PM2 管理器启动后端

1. 在面板点「软件商店」→「PM2 管理器」→「添加项目」。按表填写：

   | 字段 | 填写值 |
   |---|---|
   | 项目名称 | `lill-backend` |
   | 启动文件 / Script | `backend/ecosystem.config.cjs` |
   | 运行目录 / CWD | `/www/wwwroot/lill/backend` |
   | Node 版本 | 选择已安装的 Node 24 LTS |
   | 项目类型（如有） | Node.js；不要选择网站整站反代 |

2. 环境变量区域逐项新增 `NODE_ENV=production`、`PORT=3000`、`FRONTEND_URL=https://blog.example.com`。再生成 JWT 密钥：在面板「终端」执行 `openssl rand -hex 32`，复制输出的 64 位十六进制字符串，作为 `JWT_SECRET` 的值。把密钥保存在服务器私有配置中，不要贴进文档、公开聊天或仓库；升级时保留原值，否则重启后现有登录会失效。
3. 如果 PM2 管理器没有环境变量输入框，先不要启动项目；在「文件」→`/www/wwwroot/lill/backend/` 编辑 `ecosystem.config.cjs`，在 `env` 对象中设置上述四项，`JWT_SECRET` 字符串需用引号包裹且不要泄露。保存后回 PM2 管理器添加/重载项目。模板配置文件会被升级覆盖，修改前后应留私有备份。
4. 点「提交 / 启动」，在 PM2 管理器列表确认 `lill-backend` 状态为 online。面板终端验证：

   ```bash
   curl --fail http://127.0.0.1:3000/api/v1/install/status
   ```

   应返回安装状态 JSON；若失败，先查 PM2 项目日志、Node 版本和环境变量。
5. 后端固定监听 `0.0.0.0`，`HOST` 环境变量当前不生效；宝塔「安全」及云厂商安全组**不要放行 3000**，只开放网站所需的 80/443。此处的本机 `curl` 通过回环地址检查服务，不代表应把端口暴露到公网。

#### 5.1.8 申请 SSL 并验收

1. 在「网站」列表找到域名，点「设置」→「SSL」→「Let's Encrypt」。勾选 `blog.example.com`，按界面提示选择文件验证并点击「申请」；申请前确保域名 DNS 指向本服务器且 TCP 80 可从公网访问。
2. 申请成功后确认 SSL 页显示有效证书。回到「配置文件」，将 5.1.6 替换表中的 `ssl_certificate` 和 `ssl_certificate_key` 两行填为面板显示的证书与私钥绝对路径，保存并测试 Nginx 配置，通过后重载。
3. 在 SSL 页面开启「强制 HTTPS」，按提示确认。之后用浏览器访问 `https://blog.example.com/admin/`，应进入安装向导；填写站点名称、HTTPS 地址和管理员账号完成初始化。
4. 在服务器终端把下列命令中的域名替换为自己的域名，依次执行并检查均成功；最后一个请求预期状态码为 404：

   ```bash
   curl --fail https://blog.example.com/api/v1/install/status
   curl --fail 'https://blog.example.com/api/v1/site/bootstrap?path=%2F'
   curl --fail 'https://blog.example.com/api/v1/posts?page=1&pageSize=10'
   curl --fail https://blog.example.com/feed.xml
   curl -I https://blog.example.com/themes/default/missing.js
   ```

5. 再在浏览器确认前台首页、文章链接、后台登录及主题资源可用。API 检查成功不代表静态资源齐全；上传附件时核对 Nginx `client_max_body_size` 与磁盘空间。

#### 宝塔常见坑

| 现象 | 常见原因 | 处理办法 |
|---|---|---|
| `Cannot find module 'node:sqlite'` | PM2 实际使用的 Node 低于 22.13，或面板终端与项目 Node 版本不同 | 版本管理器安装 Node 24 LTS，并同时将「命令行版本」和 PM2 项目 Node 设为该版本；查看 PM2 日志确认实际运行环境 |
| 前台能打开但接口 502 | 后端没启动、PM2 使用错误运行目录/Node，或 Nginx 上游端口不一致 | 在 PM2 确认 online；终端运行本机安装状态 curl；核对 `/api/` 代理到 `127.0.0.1:3000` |
| `/sitemap.xml` 返回首页 HTML | 整体替换时漏掉 `location = /sitemap.xml`，请求被前端通用回退接走 | 对照 `deploy/nginx.conf.example` 恢复精确 sitemap 代理规则，测试并重载 |
| 后台切换主题不生效、前台仍是旧主题 | Nginx `root` 指向前端构建暂存目录，或遗漏 `/themes/` 规则 | 将 `root` 修正为 `/www/wwwroot/lill/frontend`，保留模板中的主题静态资源规则 |
| 上传大图返回 413 | Nginx 请求体限制小于上传文件 | 在 `/api/` 代理配置中按需要设置 `client_max_body_size`（模板为 `50M`），保存、测试、重载 |
| 安装完仍提示站点已安装 | 当前目录的数据库已初始化，或部署时复用了旧 `backend/data/` | 先确认是否为已有站点及其数据；不要删除数据库来绕过向导，需新站时使用全新数据目录并做好备份 |
| 页面资源报 `Unexpected token '<'` | 缺失 JS/CSS 被配置为回退到首页 HTML，或静态根目录错误 | 保留模板中静态资源缺失返回 404 的规则，确认发布包文件位于 `frontend/` |
| SSL 申请失败 / HTTPS 配置测试失败 | 域名未指向本机、80 端口不可达或证书路径未填对 | 检查 DNS 与安全组 80/443；在宝塔 SSL 页复制证书实际路径，改完先测试再重载 |

### 5.2 1Panel

1. 准备 OpenResty 和满足要求的 Node 运行环境，按第 2 节安装程序。
2. 创建静态网站，选择实际映射到 `frontend/` 的目录。
3. 在 Node 运行环境或独立进程管理中启动后端，配置环境变量和持久化数据目录。
4. 按第 4 节配置上游与静态路由，申请并启用 HTTPS。

**容器中的 `127.0.0.1` 指向该容器自身。** OpenResty 与后端不在同一网络命名空间时，必须把示例中的上游地址（API 和 RSS 两处）改为代理可达的后端地址，例如共同容器网络中的服务名及端口，或实际可达的宿主机地址。不要假定宿主机回环地址在容器中也可用。

静态站点、上传文件需挂载到 OpenResty 可读的路径，`root` / `alias` 使用容器内路径。Node 安装目录、宿主机网关和网站目录取决于面板版本与部署方式，不能统一照抄某个 `/opt/1panel/...` 路径。验证代理应从其实际网络环境进行。

### 5.3 裸机

使用系统支持的方式安装 Node.js 24 LTS、Nginx、`zip`，源码部署另需 Git、pnpm、`rsync`。按第 2–4 节完成程序准备、PM2 和 Nginx 配置；发行版的站点配置位置及服务名以本机为准。

访问 `https://blog.example.com/admin/`，按向导检查环境、填写站点名称及 HTTPS 地址、创建管理员账号。安装会初始化站点数据与默认内容，不需要手工创建外部数据库。

## 7. 升级与备份

### 升级

1. 阅读[发布说明](发布说明.md)和[更新日志](../CHANGELOG.md)，在新目录解压发布包，或检出指定版本并按源码步骤构建。
2. 先创建并下载数据库一致性快照和附件备份，另存进程配置及完整主题、插件目录。
3. 停止后端写入，按明确文件清单同步代码和静态产物；保留 `backend/data/`、`backend/uploads/`，以及自定义 `DB_PATH` / `UPLOAD_DIR` 对应目录、固定 `JWT_SECRET`、其他私有环境变量和 PM2 配置。
4. 保留所有已安装的第三方主题及插件；官方默认主题更新单独处理，已自行修改时先比较差异，保留其运行时缓存。静态产物同步继续排除 `/themes/`。
5. 在更新后的 `backend/` 安装生产依赖，重启后端，按第 6 节检查；失败时按已保存的程序和数据备份回退。

不要直接把压缩包解压到运行目录，也不要对项目或主题总目录使用无差别删除同步。不能依赖“发布包不带数据库”来保证私有配置和第三方扩展不被覆盖。

根目录的 `deploy.sh` 含维护者固定的服务器、部署路径、本地 Node/pnpm 路径和健康检查域名，只适用于维护者当前环境，**不是通用一键安装器**。普通部署使用本文步骤。

### 备份边界

后台「备份」使用实际数据库和附件路径创建 SQLite 一致性快照（包含 WAL 中已提交数据），校验成功后提供列表与下载；数据库 `.db` 和附件 `.zip` 分别下载，附件为空时不生成 ZIP。备份存放在数据库所在目录的 `backups/` 下，创建备份时会清理超过 30 天的备份产物，请另存异机副本。

运行中直接复制 `lill.db` 可能漏掉 WAL 数据。备份尚无一键恢复流程，也不承诺数据库与附件之间的原子快照；不包含磁盘上的主题、插件和私有配置，这些需单独保存。

附件打包需要系统 `zip`，期限为 120 秒；备份请求后端期限为 150 秒，`/api/` 反向代理应保留 `proxy_read_timeout 160s`，普通 API 后端期限仍为 20 秒。

### 维护命令

```bash
pm2 list
pm2 logs lill-backend --lines 50
pm2 restart lill-backend
```

变更进程环境变量后，按实际托管方式重新加载配置；PM2 可重新加载已配置的 `ecosystem.config.cjs` 并 `pm2 save`。固定密钥正常升级时保持不变，泄露时应立即轮换，现有登录会失效。

## 8. 常见问题

| 现象 | 检查 |
|---|---|
| `node:sqlite` 无法加载 | 确认进程实际使用 Node 24 LTS 或至少 22.13.0，不能只看终端的 `node -v` |
| API 502 | 查进程日志、端口和代理可达地址；容器中尤其要核对网络 |
| 页面白屏或 `Unexpected token '<'` | 检查静态文件是否落在 `frontend/`、资源请求是否错误回退到 HTML |
| 自定义永久链接打不开 | 保留 `/index.html` 通用回退，确认 bootstrap 收到实际路径 |
| RSS 返回 API 不存在 | `/feed.xml` 必须代理到 `/api/v1/feed` |
| 切主题后仍是旧样式 | 删除 `/theme.js` 的主题专属 alias，检查静态根目录与后端是否共享同一主题树 |
| 上传或备份失败 | 检查实际目录权限、磁盘空间、系统 `zip`、上传体积和代理超时 |
| 重启后登录失效 | 确认固定 `JWT_SECRET` 已写入实际运行配置 |
| 面板终端找不到 Node | 使用面板提供的终端或实际 Node 可执行文件路径，不假定所有面板安装目录一致 |

功能差距与限制见 [Typecho 1.3 功能对照](Typecho1.3功能对照.md)，不应将部署成功理解为已全面实现 Typecho 功能。
