# lill 主题开发指南

> 适用版本：lill v2（Node.js + Astro 静态前端 + SQLite）
> 主题 = **一个模板文件夹**。拷贝进 `frontend/themes/` 即可使用，**不需要写任何 JS 适配器**。

---

## 0. 一分钟理解 lill 主题

| | Typecho | WordPress | **lill** |
|---|---|---|---|
| 主题形态 | 文件夹 + PHP 模板 | 文件夹 + PHP 模板 | 文件夹 + **HTML 模板** |
| 渲染位置 | 服务端 PHP | 服务端 PHP | 浏览器（数据来自 REST API） |
| 模板标签 | `<?php $this->title() ?>` | `<?php the_title() ?>` | `{$post.title}` |
| 条件判断 | `<?php if(...): ?>` | `<?php if(...): ?>` | `{if $post.sticky}` |
| 循环 | `while($this->next())` | `have_posts()` | `{loop $posts as $post}` |
| 引入片段 | `$this->need('header.php')` | `get_header()` | `{include header}` |
| 主题设置 | `themeConfig` | Customizer | `theme.json` 的 `settings` |

一句话：**把 PHP 模板换成 HTML + 花括号标签**，其余思路完全一致。

## 1. 目录结构

```
frontend/themes/<主题ID>/
├── theme.json          # 【必须】主题清单：id / name / version / settings
├── index.html          # 【必须】首页（同时是所有页面的兜底模板）
├── post.html           # 文章详情
├── page.html           # 独立页面
├── archive.html        # 归档
├── category.html       # 分类
├── tag.html            # 标签
├── search.html         # 搜索
├── 404.html            # 404
├── header.html         # 片段（用 {include header} 引入）
├── footer.html
├── sidebar.html
├── style.css           # 主题样式（可选）
├── theme.js            # 主题增强脚本（可选，按需加载）
├── head.html           # 追加到 <head> 的内容（可选）
└── assets/             # 图片、字体等静态资源（可选）
```

规则：

- **主题 ID = 目录名 = `theme.json` 的 `id`**，只允许字母、数字、`-`、`_`。
- `index.html` 是唯一硬性要求；其余模板缺失时会**自动回退到 `index.html`**。
- 只有 `theme.json` / `*.html` / `*.css` / `*.js` / `assets/**` 会被发布；`*.php`、`cache/`、`src/` 等一律忽略。
- 目录名以 `_` 开头表示「不发布」（用于放旧主题备份）。

## 2. theme.json 规范

```jsonc
{
  "id": "my-theme",              // 必须，与目录名一致
  "name": "我的主题",             // 必须，后台显示名
  "version": "1.0.0",            // 必须，语义化版本
  "description": "一句话简介",    // 可选
  "author": "作者名",             // 可选
  "settings": [                  // 可选：后台「外观 → 设置」自动生成表单
    {
      "group": "外观",            // 分组名，同组自动归类（对标 Typecho themeConfig 的分组）
      "key": "color",            // 变量名，模板里用 {$theme.color} 读取
      "label": "主题色",
      "type": "color",           // color | select | text | textarea | checkbox | number
      "default": "#4f46e5",
      "options": [               // 仅 type=select
        { "value": "right", "label": "右侧栏" },
        { "value": "left",  "label": "左侧栏" }
      ]
    }
  ],
  "templates": [                 // 可选：独立页面自定义模板（对标 Typecho 的 page-xxx.php）
    { "file": "page-links.html", "name": "友情链接" }
  ]
}
```

后台保存后的值，在模板中通过 **`{$theme.<key>}`** 读取；`checkbox` 为字符串 `"true"` / `"false"`，直接写在 `{if}` 里即可（`"false"` 是**非空字符串，为真**，因此需要判断时请用 `{if $theme.key == 'true'}`）。

## 3. 模板标签语法

### 3.1 输出变量（自动 HTML 转义）

```html
<h1>{$post.title}</h1>
<time>{$post.published_at|date}</time>
```

- 默认**自动转义**，防 XSS。
- 输出富文本正文时加 `|raw`：`{$post.html_content|raw}`。

### 3.2 过滤器

语法：`{$变量|过滤器}` 或 `{$变量|过滤器:参数1:参数2}`（**参数用冒号分隔**）。

| 过滤器 | 说明 | 示例 |
|---|---|---|
| `raw` / `safe` | 不转义，输出原始 HTML | `{$post.html_content\|raw}` |
| `escape` / `e` | 强制转义 | `{$x\|escape}` |
| `date` | 格式化时间，默认 `Y-m-d` | `{$post.published_at\|date}`、`{$post.published_at\|date:'Y年m月d日'}` |
| `default` | 空值时给默认 | `{$site.description\|default:'暂无简介'}` |
| `truncate` | 截断（先剥标签） | `{$post.excerpt\|truncate:120}` |
| `upper` / `lower` | 大小写 | `{$tag.name\|upper}` |
| `length` / `count` | 长度 / 数量 | `{$posts\|count}` |
| `nl2br` | 换行转 `<br>` | `{$c.content\|nl2br}` |
| `strip` | 去除 HTML 标签 | `{$post.excerpt\|strip}` |
| `urlencode` | URL 编码 | `{$keyword\|urlencode}` |
| `number` | 转整数 | `{$post.view_count\|number}` |
| `json` | 输出 JSON | `{$post.fields\|json}` |

过滤器可链式：`{$post.excerpt|strip|truncate:80}`。

### 3.3 条件判断

```html
{if $post.sticky}<span>置顶</span>{/if}

{if $theme.show_author && $post.author_nickname}
  <span>{$post.author_nickname}</span>
{elseif $post.category_name}
  <span>{$post.category_name}</span>
{else}
  <span>未分类</span>
{/if}
```

支持 `&&`、`||`、`!`、括号，也支持 `and` / `or` / `not`。

### 3.4 循环

```html
{loop $posts as $post}
  <article>
    <a href="{$post.url}">{$post.title}</a>
  </article>
{/loop}

<!-- 需要下标时 -->
{loop $tags as $i => $tag}
  <a href="{$tag.url}">{$tag.name}</a>
{/loop}
```

循环变量名任意（`$post` / `$item` / `$c` 都行），只在该循环内有效。

### 3.5 引入片段

```html
{include header}
{include sidebar}
{include footer}
```

片段与主模板**共享同一个作用域**，因此 `header.html` 里可以直接用 `{$site.name}`、`{$nav}`。
片段可以嵌套 include（引擎会递归加载）。

### 3.6 注释

```html
{* 这段不会输出 *}
```

> ⚠️ CSS / JS 里的大括号不会被误判：只有 `{` 后面紧跟 `$`、`if`、`loop`、`include`、`else`、`/if` 等关键字时才当作标签。

## 4. 模板文件 ↔ 页面类型

| 页面 | 模板 | 触发 URL |
|---|---|---|
| 首页 / 文章列表 | `index.html` | `/` |
| 文章详情 | `post.html` | `/post/<slug>`、`/archives/<cid>/` |
| 独立页面 | `page.html` | `/page/<slug>` |
| 归档 | `archive.html` | `/archive`、`/archive?month=2026-10` |
| 分类 | `category.html` | `/category/<slug>` |
| 标签 | `tag.html` | `/tag/<slug>` |
| 搜索 | `search.html` | `/search?q=关键词` |
| 404 | `404.html` | 任意不存在的路径 |

缺失的模板会自动回退到 `index.html`，因此**最小主题只需要 `theme.json` + `index.html`**。

### 4.1 独立页面自定义模板（page-*.html）

对标 Typecho 的「页面模板」（`page-links.php`、`page-full.php`），lill 用同一套规则：

1. 在主题目录放 `page-<名字>.html`，例如 `page-links.html`、`page-full.html`。
2. 后台 **管理 → 独立页面 → 编辑页面** 会出现「页面模板」下拉，选中即生效。
3. 显示名（下拉里的文字）按以下优先级取：
   - 文件首行的注释：`<!--! 友情链接 -->` 或 `<!-- name: 友情链接 -->`
   - `theme.json` 的 `templates: [{ "file": "page-links.html", "name": "友情链接" }]`
   - 文件名（`page-links`）
4. 选中的模板 key（不含 `.html`）保存在该页面的 `template` 字段里。
5. **容错**：主题里没有对应文件、或换了主题导致文件不存在时，自动回退到 `page.html` → `index.html`，不会白屏。
6. 主题里一个 `page-*.html` 都没有时，后台不显示该下拉（与 Typecho 一致）。

模板写法与普通模板完全一致（`{include header}` / `{$post.title}` …），例如：

```html
<!--! 友情链接 -->
{include header}
<main class="main-content">
  <h1>{$post.title}</h1>
  <div class="post-content">{$post.html_content|raw}</div>
</main>
{include footer}
```

> 与 Typecho 的差异：Typecho 的模板是 PHP，可以直接查库；lill 的模板是纯 HTML + 标签，数据全部来自 bootstrap（见第 5 节），所以自定义页面模板能拿到的变量和 `page.html` 完全相同。

> 📌 如果自定义页面需要「模板专属数据」（例如友链页要读 `links` 表），
> 主题可以在 `backend/index.js` 里导出 `pageTemplate(key, info)` 往 `data` 上注入，
> 模板用 `{$data.xxx}` 读取。完整契约见 **[主题后端扩展开发指南](./主题后端扩展开发指南.md)**。

## 5. 可用数据

每次页面加载，前端只请求一次 `GET /api/v1/site/bootstrap`，返回下列结构（模板里全部可直接使用）：

### 5.1 全局变量（所有页面都有）

```
$site         { name, description, url, year }
$page         { type, slug, url, title, query:{ page, q, month } }
$theme        { ...theme.json settings 中保存的值 }
$themeMeta    { id, name, version, description, author, settings }
$options      { site_name, site_description, posts_per_page, comment_moderation, ... }
$nav          [ { title, url, type, slug, active } ]
$sidebar      { recentPosts, categories, tags, archives, recentComments }
```

`$sidebar` 各字段结构：

```
recentPosts     [ { title, url, published_at, ... } ]
categories      [ { name, slug, url, post_count } ]
tags            [ { name, slug, url, post_count } ]
archives        [ { ym, count } ]              // ym 形如 2026-10
recentComments  [ { id, author, content, created_at, post_url, post_title } ]
```

### 5.2 按页面类型追加的变量

**`index.html` / `category.html` / `tag.html` / `search.html`**

```
$posts        [ 文章对象 ]          // 当前页列表
$pagination   { total, page, pageSize, totalPages, hasNext, hasPrev }
$category     { name, slug, url, post_count, ... }   // 仅 category
$tag          { name, slug, url, post_count }        // 仅 tag
$keyword      string                                  // 仅 search
```

**`archive.html`**

```
$groups       [ { ym, count, posts: [ ... ] } ]   // 按年月分组
$month        string                              // 形如 2026-10，未筛选为空
$posts        [ 文章对象 ]                         // 全部（已按月份筛选）
```

**`post.html` / `page.html` / `page-*.html`**

```
$post             文章对象（含 html_content / tags / prev / next / template）
$comments         [ { id, author, avatar, content, created_at, replies: [...] } ]
$commentMeta      { total }
$commentAllowed   boolean
```

**`page-*.html` 额外**

```
$pageTemplate     string    // 当前生效的页面模板 key，例如 page-links
$page.template    string    // 同上（$page 对象里也有一份）
$page.templateName string   // 模板显示名，例如「友情链接」
```

**`404.html`**

```
$notFound     true
```

### 5.3 文章对象字段

```
id  title  slug  excerpt  cover_image  view_count  sticky  comment_count
published_at  created_at  author_nickname  author_avatar
category_name  category_slug  category_id
url  route  permalink  date
html_content   // 仅文章详情页
tags           // 仅文章详情页：[ { name, slug } ]
prev / next    // 仅文章详情页：{ title, url } 或 null
```

## 6. 评论表单（主题只需写 HTML）

在 `post.html` 里放一个带固定 class 的表单，运行时自动接管提交：

```html
<form class="lill-comment-form" data-post-id="{$post.id}">
  <input type="text"  name="authorName"  placeholder="昵称 *" required>
  <input type="email" name="authorEmail" placeholder="邮箱（不会公开）">
  <input type="url"   name="authorUrl"   placeholder="网站（可选）">
  <textarea name="content" rows="4" placeholder="说点什么..." required></textarea>
  <span class="lill-comment-msg"></span>
  <button type="submit">发表评论</button>
</form>
```

- 必填：`class="lill-comment-form"`、`data-post-id`、字段名 `authorName` / `authorEmail` / `authorUrl` / `content`。
- 可选：`.lill-comment-msg` 用于显示成功 / 失败提示。

## 7. 深色模式开关（可选）

```html
<button data-lill-toggle="dark">切换深色</button>
```

点击后会给 `<html>` 切换 `lill-dark` class（并记忆到 `localStorage`）。样式里写：

```css
html.lill-dark body { background: #111; color: #eee; }
```

## 8. 从 Typecho / WordPress 移植

| Typecho | lill |
|---|---|
| `$this->title()` | `{$post.title}` |
| `$this->content()` | `{$post.html_content\|raw}` |
| `$this->date('Y-m-d')` | `{$post.published_at\|date:'Y-m-d'}` |
| `$this->author()` | `{$post.author_nickname}` |
| `$this->category()` | `{$post.category_name}` |
| `$this->permalink()` | `{$post.url}` |
| `$this->need('header.php')` | `{include header}` |
| `$this->widget('...')` | `{$sidebar.recentPosts}` 等 |
| `while($this->next())` | `{loop $posts as $post}` |
| `if($this->is('post'))` | `{if $page.type == 'post'}` |
| `$this->options->siteUrl` | `{$site.url}` |
| `$this->options->title` | `{$site.name}` |
| `page-links.php`（页面模板） | `page-links.html`（同名，首行写 `<!--! 显示名 -->`） |
| 页面模板名存 `table.contents.template` | 页面模板名存 `posts.template` |

移植步骤：

1. 新建目录 `frontend/themes/<id>/`，放入 `theme.json`。
2. 把 `index.php` / `post.php` / `page.php` … 改名为 `index.html` / `post.html` / `page.html`。
3. 按上表替换 PHP 输出为 `{...}` 标签。
4. 把 `header.php` / `footer.php` / `sidebar.php` 改成 `.html` 片段，用 `{include}` 引入。
5. 静态资源放进 `assets/`，CSS 里用相对路径引用。
6. 主题设置搬到 `theme.json` 的 `settings`，模板里用 `{$theme.key}` 读取。
7. 页面模板 `page-*.php` 直接改名成 `page-*.html`，后台编辑独立页面时即可在下拉里选到。
8. 刷新页面即可看到效果——**无需重新构建、无需改后端代码**。

## 9. 安装 / 切换主题

**方式一：后台上传（推荐）**
后台 → 外观 → 安装主题 → 上传主题 ZIP（包内需含 `theme.json`）→ 安装后点「启用」。

**方式二：手动拷贝**
把主题文件夹拷进 `frontend/themes/`，重启后端（`pm2 restart lill-backend`）即可在后台看到。

> 主题若带后端扩展（`backend/index.js`），重启后端时会自动加载并打印 `✓ 主题扩展已加载：<id>`。
> 详见 **[主题后端扩展开发指南](./主题后端扩展开发指南.md)**。

**主题设置**：后台 → 外观 → 对应主题卡片上的「设置」按钮，按 `theme.json` 的 `group` 自动分组渲染。

## 10. 最小可用主题示例

`frontend/themes/mini/theme.json`

```json
{
  "id": "mini",
  "name": "Mini",
  "version": "1.0.0",
  "description": "最小主题示例",
  "author": "you",
  "settings": [
    { "group": "外观", "key": "color", "label": "主题色", "type": "color", "default": "#4f46e5" }
  ]
}
```

`frontend/themes/mini/index.html`

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>{$site.name}</title>
  <link rel="stylesheet" href="/themes/mini/style.css">
</head>
<body>
  <header>
    <a href="/">{$site.name}</a>
    <nav>{loop $nav as $item}<a href="{$item.url}">{$item.title}</a>{/loop}</nav>
  </header>

  <main>
    {loop $posts as $post}
      <article>
        <h2><a href="{$post.url}">{$post.title}</a></h2>
        <p>{$post.excerpt|truncate:100}</p>
      </article>
    {/loop}
  </main>

  <footer>{$site.name} © {$site.year}</footer>
</body>
</html>
```

`frontend/themes/mini/style.css`

```css
body { font-family: system-ui, sans-serif; max-width: 720px; margin: 0 auto; color: var(--primary); }
```

> ⚠️ `style.css` 是**静态文件**，不会经过模板引擎。主题色请用内联 style 或 CSS 变量注入：
> 引擎会自动把 `$theme.color` 写到 `--primary` CSS 变量上（见 `applyThemeBody`），
> 因此在 CSS 里直接使用 `var(--primary)` 即可。

完整可运行范例见仓库 `frontend/themes/default/`（含 8 个模板 + 5 个片段）。

## 11. 调试技巧

- 浏览器控制台报「主题「x」缺少 y.html 模板」→ 该模板文件不存在且回退失败。
- 页面空白 → 打开控制台看是否有「主题模板渲染失败」，多半是标签写错（如 `{if}` 没闭合）。
- 想临时查看全部数据 → 控制台执行 `window.__LILL_SCOPE__`。
- 修改模板后**直接刷新即可**（模板按需拉取，不缓存），不需要重新构建前端。
