# lill 安全与公开内容隔离设计

**日期：** 2026-10-11
**范围：** 第一批安全优化

## 目标

封闭未授权的数据破坏与内容读取路径，并让所有后台 API 按当前用户状态和角色实施一致的授权；确保公开接口只返回允许访客读取的文章数据。

## 当前根因

- 安装重置 API 以 `auth = false` 注册，只比较固定请求字段便删除数据库表。
- 多个公开文章 API 接受调用方提供的状态，或按 slug 查询时没有统一状态与可见性条件。
- `/admin/*` 路由大多只要求有效 JWT，业务处理器未统一检查角色和资源所有权。
- JWT 的角色声明在令牌签发时确定；账号禁用或角色调整后，现有令牌仍可能携带旧权限。
- `posts` 含 `visibility` 与 `password` 字段，公开序列化不能原样返回数据库记录。

## 设计

### 安装与破坏性操作

- 移除公开的 `POST /api/v1/install/reset` 路由。重置不属于正常安装流程，不保留匿名重置能力。
- 安装状态查询与首次安装流程继续可匿名访问；安装完成后仍由现有 `isInstalled()` 防止重复创建站点。
- 后台备份、恢复等操作不在本批增加新能力，但必须纳入管理员权限保护。

### 公开内容策略

- 所有访客内容入口统一遵循相同规则，包括主题 bootstrap、文章列表、slug 详情、页面列表、归档及分类/标签内容计数。
- 仅允许 `status = 'published'` 且 `visibility = 'public'` 的内容进入公开结果。访客传入状态参数不能放宽条件。
- 现阶段没有已验证的密码文章验证流程；因此密码或非公开可见性文章不向匿名公开 API 返回。后续如实现密码文章访问，应单独定义验证与授权流程。
- 公开 DTO 使用显式字段白名单，不返回密码、用户隐私字段或未发布关联数据。
- 不改变管理 API 对草稿、待审核、回收站内容的访问能力；该访问必须受角色权限保护。

### 身份与角色授权

- 每次受保护请求除验证签名和过期时间外，还要以数据库中的当前账号状态与角色为准；停用或不存在的账号不能继续使用旧 JWT。
- 在路由装配层使用统一认证/授权策略，避免依赖每个处理器自行记得检查角色。
- 权限矩阵：

| 角色 | 内容权限 | 分类/标签 | 评论 | 媒体 | 系统与扩展 |
|---|---|---|---|---|---|
| 管理员 | 管理全部文章和页面 | 全部管理 | 管理全部评论 | 全部管理 | 用户、设置、主题、插件、备份、日志 |
| 编辑 | 管理全部文章和页面 | 全部管理 | 管理全部评论 | 全部管理 | 不可管理用户、系统设置、主题、插件或备份 |
| 作者 | 创建、发布和管理自己的内容 | 不可管理 | 不可管理全站评论 | 上传和管理自己的媒体 | 不可管理系统与扩展 |
| 投稿者 | 创建和管理自己的草稿；不能自行发布 | 不可管理 | 不可管理全站评论 | 上传和管理自己的媒体 | 不可管理系统与扩展 |
| 订阅者 | 不可访问后台内容管理 API | 不可管理 | 不可管理 | 不可管理 | 不可管理系统与扩展 |

- 所有资源级操作检查资源归属；批量接口逐项执行同等授权，不能因批量入口绕过单项规则。
- 媒体访问按角色和上传者归属限制；作者/投稿者不能通过列表、读取或删除接口访问他人的媒体。
- 高权限能力包括但不限于：用户角色/状态管理、全站设置、主题文件读写/安装/启用、插件安装/启停/配置、备份下载/创建和系统操作。
- 未授权请求返回统一 `403`；未认证、令牌过期、账号停用返回统一 `401`，响应不包含敏感内部信息。

## 测试与验收

- 使用隔离的临时 SQLite 数据库和临时上传/扩展目录运行真实 HTTP 请求；不得使用或改写仓库中的 `data/lill.db`。
- 匿名请求无法重置数据库；该路由返回 `404`。
- 列表、详情和 bootstrap 在尝试请求草稿、私有或带密码文章时均不返回其内容及密码字段。
- 每种角色对允许和禁止的 API 操作返回预期的 `2xx`、`401` 或 `403`；资源所有权和批量操作覆盖正反用例。
- 用户停用或角色降权后，之前签发的 JWT 不再保留旧权限。
- 既有主题、插件与公开内容读取测试继续通过；测试不依赖源码字符串匹配来代替 API 行为验证。

## 非目标与后续批次

- 本批不合并 `server.js` 与 `db.js` 的数据库定义，不运行现有站点数据库迁移。
- 本批不重做发布/部署脚本，不连接测试站或线上服务器。
- JWT 密钥从仓库移除与轮换、请求体大小限制、CSRF 长度比较和跨域头配置、文件路径 containment、Markdown URL 协议过滤、主题目录配置一致性，列入后续安全/运维批次；不得以本规格验收通过代表这些问题已解决。
- 不新增密码文章验证功能，不重写认证协议或前端管理界面。
