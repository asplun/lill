# Typecho 1.3 功能对照与缺陷清单

审计日期：2026-10-18。

- lill 基线：`d9e17c6e06d1fd495423b08d11cf054c33fefdcd`。
- Typecho：官方 `v1.3.0`，提交 `e9f23304bf20c0c355ef1df9634d42148cbc53b5`。
- 对照官方完整源码，同时检查 lill 的界面、接口、数据库及公开读取路径。部分问题通过隔离 SQLite 内存数据库及真实处理函数复现；不代表已在线上触发。
- 下列项目仍待处理。本次已完成的后台请求与导航修复单列在文末，不能据此认为功能已全面对齐。

P1 优先处理内容正确性、安全和基础可用性；P2 补齐日常管理流程。数据库有字段、接口接受参数，不等于用户能完整使用。

## 优先修复的实际问题

| 编号 | 优先级 | 已确认的问题 | 影响与最小处理方向 |
| --- | --- | --- | --- |
| B01 | P1 | 文章列表不返回 `type`，编辑按钮却把它拼成字符串 `"undefined"` 提交 | 从列表编辑保存后，记录可能离开文章查询范围。固定文章入口类型，并在服务端校验 `post/page`。 |
| B02 | P1 | 清空正文时只更新原文，不重算 HTML | 前台可能继续显示已清空的旧内容。空字符串也必须同步更新派生字段。 |
| B03 | P1 | 中文标签重复保存时按不稳定 slug 查找，撞上名称唯一约束 | 保存报错之前正文可能已更新。按稳定 ID/名称复用标签，将文章、关联与版本快照放入同一事务。 |
| B04 | P1 | 写入 API 静默忽略 `visibility/password` | 客户端要求私密或密码保护，实际可能创建为公开。未支持的保护参数应明确拒绝，再补完整权限与密码验证。已有受限记录当前会被公开查询排除，不能据此声称已有私密记录全部泄露。 |
| B05 | P1 | 插件配置统一保存为 `autoload=1`，公开 options/bootstrap 返回全部此类选项 | 用无敏感哨兵值已确认配置会公开；未声称发现真实密钥泄漏。公开选项应使用白名单，插件配置默认私有，兼顾既有数据。 |
| B06 | P1 | 备份从主题目录推导数据库与附件位置，没有使用实际运行路径 | 可能复制错误、旧的或空数据库后提示成功。使用实际数据库连接及附件路径，并采用支持 WAL 的一致性快照，不能只复制主库文件。 |
| B07 | P1 | 首次安装在读取请求体前检查状态，事务内没有再次检查 | 隔离验证中两个并发请求均创建了管理员。把安装检查与写入放进原子保护。此项不代表 Typecho 已通过相同并发安全测试。 |
| B08 | P1 | 评论审核设置被所有登录用户直接绕过 | 开放注册后 subscriber 也能免审。仅有相应文章编辑权限者免审，其余遵循审核设置。 |
| B09 | P1 | 永久链接仅改变生成字符串，没有统一的路径解析与静态壳回退 | 内置部署仍依赖固定路由；消费不同 URL 字段可能表现为设置无效或链接打不开。生成和解析应共享规则。外部自定义代理可能另有适配，本次未验证。 |
| B10 | P2 | 后台菜单、默认控制台请求及编辑器状态未按角色调整 | 非管理员登录后遇到 403；投稿者默认发布状态与后端仅允许草稿的策略冲突。用小型能力映射约束界面，保留服务端权限检查。 |
| B11 | P2 | 评论回复/编辑只重新查询最新 100 条 | 老评论能分页看到，却可能提示不存在。直接使用当前行完整数据，或增加受权限保护的单条读取。 |
| B12 | P2 | 批量发布不补 `published_at`；未来发布时间不阻止公开 | 单条和批量日期语义不一致，也没有完整定时公开。统一发布逻辑及公开查询的时间条件，无须先加任务队列。 |
| B13 | P2 | 摘要长度、摘要方式、文章排序等设置已保存，但消费方仍硬编码 | 设置与实际结果不一致。这些部分属于 lill 自身承诺，不全是 Typecho 的等价选项；应接通或移除无效入口。 |
| B14 | P2 | 每页条数的全站设置与主题默认值冲突；评论显示/条数未统一消费 | 修改设置后前台可能没有变化。明确全站默认、主题显式覆盖的优先级。 |
| B15 | P2 | 插件激活失败时可能仍保留启用记录或成功反馈 | 区分真实加载成功与失败，失败回滚状态并清理注册残留。 |

## 对照 Typecho 尚未闭环的细节功能

| 功能 | lill 现状 | Typecho 1.3 对照与建议 |
| --- | --- | --- |
| 自定义内容字段 | 后端可存 `fields`，编辑器没有通用入口 | Typecho 有字符、整数、小数、JSON 字段编辑。复用现有字段存储，提供通用编辑器；主题业务字段继续由主题声明。 |
| 一篇文章多个分类 | 数据模型及编辑器只有单个 `category_id` | Typecho 使用多选分类和关联表。这是模型差异，需要迁移关联表，不能只把下拉换成复选框。 |
| 发布日期 | API 有部分 `publishedAt` 写入能力，没有日期控件 | Typecho 可编辑日期并按当前时间过滤未来内容；须连同 B12 处理。 |
| 页面顺序与层级 | 更新 API 有 `order`，新建与编辑界面没有对应闭环；没有页面父子管理 | Typecho 页面编辑有顺序、父页面和目录路径。先接通顺序，再独立设计层级与路由。已有自定义页面模板功能保留。 |
| 服务端自动草稿与修订草稿 | 当前为本浏览器 localStorage 恢复；保存时写历史快照，没有完整修订管理界面 | Typecho 可将已发布文章的修改保存为独立草稿，自动保存到服务器。不能把本地恢复或历史表等同于此功能。 |
| 单篇权限控制 | 编辑器没有单篇允许评论、引用、Feed 的控制 | Typecho 有对应权限项；优先落实单篇评论控制，引用协议按实际使用需求决定。 |
| 正文摘要分割线 | 有独立摘要输入，未实现 Typecho 的 `<!--more-->` 摘要规则 | Typecho 默认依正文分割取摘要。独立摘要可保留，另接通分割语义，避免冒充 Typecho 默认字段。 |
| 内容列表筛选与批量操作 | 关键词、分类筛选和文章批量接口已有，界面没有完整操作入口 | 先复用已有接口，接通筛选、选择后操作及明确反馈。 |
| 评论按文章查看 | API 支持 `postId`，界面只有状态筛选 | Typecho 支持针对某篇内容管理评论；补按文章查看入口，不强制引入折叠式分组布局。 |
| 附件编辑与替换 | 当前主要为上传、列表和删除 | Typecho 可编辑标题、缩略名、描述，并原位替换文件。lill 缺相应编辑与替换流程；这不包括 WP 裁图等额外需求。 |
| 备份下载和恢复 | 有列表/下载 API，后台只创建并提示服务器路径；没有恢复流程 | 先修 B06，再接下载入口。Typecho 可恢复自身内容备份，但其备份不等同于完整站点快照。导入 Typecho 格式应按真实迁移需求独立实现。 |

本表用于确认差距和实现边界，不表示本轮已经新增这些功能，也不是穷尽所有差异的功能承诺。

## 已有能力与合理差异

- 主题列表、切换、按主题独立保存配置、声明式设置表单、页面自定义模板已有通路；本次未将它们重复列为缺失。任意第三方主题是否消费自己的每个设置，需要单独验证。
- 主题后端扩展与 REST API 可以保留前后端分离，无须复刻 PHP 的执行方式。
- Typecho 的 XML-RPC/Pingback 开关与 lill 自身依赖的 REST API 不等价，不应机械增加“关闭所有 API”选项。
- Typecho 1.3 核心的文章、页面、评论删除为永久删除，不能把 WordPress 回收站当作 Typecho 必须具备的功能。lill 若展示回收站，仍需兑现自己的界面承诺。
- 个人资料页此前已被用户列为不需要，保留为可选差异，不为追求对齐强加该页面。
- 第三方 trim3 的布局、业务设置和资源不属于 lill 核心。本次不迁入、删除或发布该主题。

## 本轮已修复的后台交互问题

以下与上面仍待处理的清单分开：

- 编辑器独立的文章、分类、模板、永久链接读取改为并行。
- 重复点击当前菜单不再取消并重启相同加载，失败页面仍可重试。
- 主题、插件、文章、分类、用户子页面统一处理请求取消；重试保留失败的具体子页面。
- 评论勾选、全选、取消选择只更新本地界面，不重新请求并替换整张表。
- 后台写入可在切页后完成，但旧操作不会夺回当前页面；同页并发写入仍各自刷新结果。
- 删除编辑器长期选项缓存，重新打开时读取当前设置。
- 评论回复、编辑的初始请求被取消时不再产生未捕获拒绝；B11 的最新 100 条限制仍待修复。

对应[浏览器回归测试](../backend/test/admin-ui.test.js)已在真实浏览器和临时 API/SQLite 环境运行；独立审查指出的重试、同页并发刷新与旧缓存问题也已加入回归。

验证结果：构建成功，完整测试 129 项通过、0 项跳过；后台浏览器专项包含 21 个子用例。2026-10-18 已部署后台相关四个文件，保留测试站当时启用的 trim3，部署前后校验 3221 个第三方主题文件一致。

线上只读测量得到以下两次快照，受当时网络和运行环境影响，不作为所有页面的性能保证：

| 新建页面编辑器 | 修复前 | 修复后 |
| --- | --- | --- |
| 普通网络 | 314 ms | 105 ms |
| 每个 API 请求人为附加 180 ms 延迟 | 818 ms | 322 ms |

三个前置 API 已并行发出；修复后的这次线上测量没有记录到页面脚本错误或超过 50 ms 的主线程长任务。该验收只覆盖后台交互，不代表文首仍待处理的缺陷已修复。
